COPY 详细部署教程

项目概述

COPY 是一个专为 Robinhood Chain 设计的、以 CLI 为核心的本地复制交易终端。它持续构建 Robinhood 代币宇宙，追踪盈利钱包的活动，通过 COPY 原生的流程墙评估每个交易设置，解释每一个 FIRE（开火/执行）或 SKIP（跳过）的决策，轮换 COPY 钱包镜像，标记纸上（模拟）仓位，并在同一终端中保持原生执行队列可见。

核心理念：CLI 是主要产品，浏览器层只是围绕相同数据和队列栈的可选封装。

当前构建状态：所有核心引擎均处于 WORKING（可用） 状态，包括：

  • 代币发现：不断增长的 RH 市场宇宙 + 最新优先的事件流
  • 盈利猎手：排名 Fomo 上下文 + 追踪源检查
  • COPY 决策：EDGE / DEPTH / TURN / MOMO / PRICE + 拒绝原因
  • COPY 钱包：轮换的交易者/代币镜像 + 快速 PnL 增量 + 迷你走势图
  • 纸上引擎：开仓、标记、止盈、止损、移动止损、时钟退出
  • 原生队列：服务端执行边界，无需浏览器钱包连接
  • 终端 UI：全屏 TUI、键盘控制、热雷达、源脉冲、仓位、退出

终端使用指南

启动终端

全屏终端同时保持三部分内容可见：

  1. 最新的代币 / 钱包 / 决策事件
  2. 右侧选中的决策分解
  3. 下方的 COPY 钱包工作台

主要事件类型

事件 含义
NEW 新的 Robinhood 市场进入宇宙
BUY / SELL 观察到追踪的钱包 / 盈利猎手事件
MOVE 实时市场标记发生变化
SCAN COPYBARA 重新运行流程墙
READY 候选者当前通过决策框
COPY 开启了纸上复制
PNL 未平仓的纸上仓位收到新标记
EXIT 止盈、止损、移动止损、最大持有或手动关闭
SYNC 提供商刷新完成

键盘控制

按键 功能
↑ / ↓ 在事件间移动
f 切换 ALL → FIRE → SKIP
space 将选中的 FIRE 作为 PAPER 复制开仓
c 追踪 / 取消追踪选中的源
p 暂停 / 恢复扫描器
r 立即刷新提供商
q 退出

运行模式

COPY 支持多种运行模式：

命令 功能
copy hunt 持续滚动的原始事件 / 决策流
copy hunt --fire-only 仅显示 FIRE 事件
copy hunt --for 300 运行指定秒数后退出
copy hunt --json 输出 JSON 格式，便于管道处理
copy paper 本地纸上复制循环和退出
copy paper --for 300 纸上模式运行指定秒数
copy web 可选浏览器封装 / 原生队列服务器

Hunt 模式

hunt 运行相同的引擎，但没有全屏渲染器。它适用于原始终端墙、日志记录、管道 JSON 或显示 Bodkin 风格的滚动馈送。

Paper 模式

Paper 模式监视新鲜候选者，在槽位和预算允许时开启通过的设置，重新标记仓位，并在配置的退出条件触发时关闭它们：

text

使用 copy positions 打印当前未平仓和最近关闭的纸上仓位。

COPY 流程墙（决策规则）

COPY 分数是上下文，不是许可开关。默认决策框是复制交易原生的：

墙 默认值 询问内容
EDGE COPY DNA ≥ 58 源是否足够强？
DEPTH 流动性 / 市值 ≥ 1.00% 相对于规模是否有足够深度？
TURN 24h 成交量 / 流动性 ≥ 0.45× 市场是否真的在周转？
MOMO −15% … +38% 移动是否在配置的复制区间内？
PRICE 必需 是否有新鲜标记可供交易？

常见问题排查

问题 解决方案
Node 版本过低 升级到 Node 20 或更新版本
npm run doctor 失败 检查网络连接，确认可访问 Robinhood Chain RPC
终端无数据 运行 npm run doctor 检查提供商健康状态，按 r 刷新
纸上仓位未开仓 检查 copy rules，确认决策墙设置合理
API 密钥未生效 检查 .env 文件格式，重启终端
Docker 部署问题 仓库包含 Dockerfile 和 docker-compose.yml，可使用 Docker 部署

FAQ

COPY 已经可用了吗？
是的。terminal、hunt、paper、doctor、rules、positions 和可选的 web 封装都在当前仓库中运行。

为什么高分代币仍可能被拒绝？
因为分数只是上下文。许可仍取决于 EDGE、DEPTH、TURN、MOMO、PRICE、敞口和预算。

我可以把它开着放在流媒体或通话中吗？
可以。终端设计为持续运行，添加代币、更新市场、轮换 COPY 钱包，并保持右侧窗格长期有用。

我可以稍后接入执行吗？
可以。原生队列边界已在项目中。参见 docs/SAFETY.md 和 docs/ARCHITECTURE.md。

安全提醒

在接入外部执行器之前，请阅读 docs/SAFETY.md。将签名材料保持在浏览器之外和仓库之外。
