Git 和 GitHub：装机必备，省时省力

更新于2026-09-05|toolssoftware
|总字数:3.2k|阅读时长:10分钟|浏览量:

一、先分清 Git 和 GitHub 到底是什么

Git 是用来管理项目版本的软件，通常装在电脑上。一个项目今天改了哪里、明天又改了哪里，都可以让 Git 分次记下来。即使电脑断网，仍然可以用它查看变化、找回以前的版本，或者另外留一条路线尝试新功能。

在 Git 里，一个被管理的项目通常叫“仓库”。仓库里既有项目文件，也有 Git 留下的版本记录。

GitHub 是一个在线平台，用来把这些仓库放到网上。项目放上去以后，你可以换一台电脑继续做、把项目分享给别人，也可以和别人一起修改。

只在自己的电脑上使用 Git，也能留下版本。需要把仓库放到网上保存、分享或协作时，才会用到 GitHub。

比如你有一个能正常使用的小网页，现在准备让 AI 继续修改。

此时项目只有一份，放在你的电脑里。你按下保存，index.html 里的新内容会覆盖旧内容。如果 AI 把网页改坏了，光靠保存找不回修改前的版本。

你可以把分支理解为同一个项目里的另一条修改路线。它不会复制项目文件夹，也不会从 GitHub 重新下载项目。

五、想修改别人的项目，先 Fork 到自己的账号

前面一直在改你自己的待办项目，修改后可以直接 push 到自己的 GitHub 仓库。

如果你想在别人的开源项目基础上继续修改，情况就不同了。你通常没有原仓库的写入权限，不能直接把修改 push 上去。

先打开原仓库，点击右上角的 Fork，再点击 Create fork。GitHub 会在你的账号下创建一份仓库，原仓库不会发生变化。

现在 GitHub 上有两份仓库：

  • 原作者的仓库，你没有写入权限；
  • 你账号下的 Fork，你可以向这里 push。

进入你账号下的 Fork，点击 Code，复制仓库地址。打开准备存放项目的文件夹，在终端里先输入 git clone 和一个空格，再粘贴刚复制的地址，按回车。这个地址就用在这里。

下载完成后，进入项目文件夹。电脑里的这份项目连接的是你账号下的 Fork，可以直接修改。

不管修改的是自己的仓库，还是从 Fork 下载的仓库，本地都会反复用到检查改动、提交版本和上传到 GitHub。这几步其实也可以让 AI 帮你做。

看到这里，你已经弄懂 Git 和 GitHub 怎么配合了

Git 负责在电脑里记录修改，GitHub 负责保存网上的仓库。你已经知道怎样把本地修改存成版本、传到 GitHub，也知道换电脑后怎样把项目下载回来继续搞。

分支是在同一个项目里保留另一条修改路线，Fork 是把别人的仓库复制到自己的账号。再看到 clone、pull、push 这些命令，你能看出它们是在下载、更新还是上传项目。

命令不用一次全背下来，边用边查就行。 能分清项目现在在哪儿、仓库是谁的、修改要去哪里，你已经掌握了 Git 和 GitHub 的精髓了。
