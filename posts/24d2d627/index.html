Multica 完整部署教程：AI 智能体协作平台

更新于2026-09-05|aiagent
|总字数:1.7k|阅读时长:5分钟|浏览量:

Multica 是一个开源的工作区平台，让你能够将 AI 编程智能体（如 Claude Code、Codex、Cursor 等）像团队成员一样分配任务。它提供了一个统一的界面来管理智能体、任务和代码审查，支持自托管部署，确保你的代码和上下文完全可控。

本教程将指导你完成 Multica 的部署，涵盖快速体验（云服务）、一键自托管脚本和高级开发环境搭建。

🚀 方案一：快速体验 (云服务/桌面应用)

这是最快捷的体验方式，无需自己管理服务器，适合个人或小团队快速上手。

  1. 访问官网：在浏览器中打开 multica.ai 并注册/登录账号。
  2. 下载桌面应用（可选）：从 multica.ai/download 下载适用于 macOS、Windows 或 Linux 的桌面客户端。桌面应用会自动将你当前使用的计算机注册为一个“运行时”（Runtime），并检测已安装的智能体 CLI。
  3. 添加更多运行时（可选）：如果你需要让智能体在云端或另一台机器上工作，可以在 Web 界面左侧边栏打开 Runtimes，点击 Add a computer，然后在目标机器的终端中粘贴并运行给出的两条命令。
  4. 创建智能体：在侧边栏 Agents 中点击 New agent，选择一个已连接的运行时、一个智能体提供商（如 Claude Code），并为其命名。你可以使用 Build with AI 功能通过自然语言描述来生成配置。
  5. 分配任务：创建一个 Issue 并将其分配给该智能体。智能体会自动领取任务，在你的机器上执行，并在过程中留下评论，最后将 Issue 移至审查状态。

🖥️ 方案二：自托管部署 (推荐生产使用)

Multica 允许你将整个平台（包括后端、数据库和 Web 界面）部署在自己的基础设施上。官方提供了一键安装脚本和 Docker Compose 两种主要方式。

⚙️ 关键配置与概念

成功部署后，了解以下核心概念有助于你更好地使用 Multica：

  • 运行时 (Runtime)：运行智能体 CLI 的实际机器（你的笔记本电脑或云服务器）。你需要在每台用于执行任务的机器上安装并配置好至少一个支持的智能体 CLI（如 claude, codex）。
  • 智能体 (Agent)：对特定 AI 编程助手的配置封装。你可以为同一个提供商（如 Claude Code）创建多个不同名称的智能体，用于不同的项目或权限。
  • 项目 (Project)：将相关的代码仓库、文档和任务组织在一起，为智能体提供必要的上下文。
  • 技能 (Skills)：将常见问题或解决流程封装成可复用的知识库，所有智能体都可以调用。
  • 小队 (Squads)：将多个智能体或人类成员组合成一个团队，由队长负责分配工作。

🔧 常见问题与排障

  • 智能体无法启动或执行任务：
    1. 检查目标 运行时 是否在线且连接正常。
    2. 确保该机器上已安装并登录了对应的智能体 CLI（如 claude, codex）。
    3. 查看任务的 执行日志 (Execution log)，其中会详细记录每一步的工具调用、命令和错误信息。
  • 自托管时端口冲突：
    修改 docker-compose.selfhost.yml 文件中的端口映射（如 "80:80"），或者修改 .env 文件中的相关配置。
  • 数据库迁移失败：
    确保 PostgreSQL 服务已完全启动且 .env 中的数据库连接字符串正确。在开发环境下，可以手动运行 make migrate。
  • 更新部署：
    • 自托管脚本：重新运行安装脚本即可。
    • Docker Compose：git pull 拉取最新代码，然后重新执行 docker-compose -f docker-compose.selfhost.yml pull && docker-compose -f docker-compose.selfhost.yml up -d。
    • 开发环境：git pull 后，运行 make dev 会自动更新依赖和数据库。

⚖️ 许可与重要说明

  • 许可证：Multica 采用 Multica 许可证，其核心是 Apache License 2.0，但附加了关于托管服务、商业嵌入和品牌使用的额外条件。请仔细阅读项目根目录下的 LICENSE 和 NOTICE 文件。
  • 智能体 CLI：Multica 不提供或分发任何智能体 CLI（如 Claude Code）。你需要自行安装、登录并管理这些工具的许可证和使用。
  • 安全：Multica 的设计强调安全。你可以通过 角色 (Roles) 和 访问范围 (Access Scopes) 精确控制每个成员可以运行哪些智能体，以及智能体可以访问哪些资源。

至此，你已掌握部署 Multica 的主要方法。根据你的需求选择最适合的方案，开始构建你的 AI 与人类混合团队吧。如需更详细的配置选项，请查阅项目文档中的 Self-Hosting Guide。
