Condor 是 Hummingbot 基金会推出的开源 AI 交易代理管理框架

Condor 详细部署教程

项目概述

Condor 是 Hummingbot 基金会推出的开源 AI 交易代理管理框架。它将 LLM 驱动的决策与确定性的交易执行通过 Hummingbot API 连接起来，让你能够部署可以观察市场、推理策略并执行交易的自主 AI 代理。

核心特性：

特性 说明
投资组合仪表板 全面的投资组合视图，包含 PNL 追踪、24小时变化和图形分析
机器人监控 追踪活跃的 Hummingbot 交易机器人，实时状态和指标
CLOB 交易 在中心化交易所（Binance、Bybit 等）通过交互式菜单下单
DEX 交易 通过 Gateway 交换代币和管理 CLMM 流动性头寸
Web 仪表板 浏览器 UI（通过 /web），包含实时交易面板
AI 助手 通过 /agent 提供自然语言交易帮助
AI 代理 领域代理，可以自主运行，支持干跑模式

部署前准备

系统要求

根据官方文档，系统要求如下：

组件 最低要求 推荐配置
操作系统 Linux x64 或 ARM (Ubuntu 20.04+)、macOS Ubuntu 22.04 LTS
内存 4 GB RAM 8 GB RAM
存储 10 GB SSD 20 GB SSD
CPU 2 vCPU 4 vCPU

Windows 用户：需要安装 WSL2 与 Ubuntu，然后在 Ubuntu 内使用终端。

云服务器选项

任何云服务商都可以。热门选择包括：

  • AWS EC2：t3.medium 或更大
  • Google Cloud：e2-medium 或更大
  • Digital Ocean：4GB RAM 的基本 Droplet
  • Hetzner：CX21 或更大

前置条件

  1. Mac 或 Linux 计算机（Windows 用户需 WSL2 + Ubuntu）
  2. 终端应用已打开
  3. 稳定的互联网连接
  4. Docker（Mac/Windows 用 Docker Desktop，Linux 用 Docker），需在运行命令前安装并运行
  5. Tailscale 账户（免费版即可）—— 推荐用于生产环境

Tailscale 配置（推荐用于生产）

Tailscale 创建一个私有的 WireGuard 网络（tailnet），让 Condor 可以安全地访问 Hummingbot API，而无需公开暴露 8000 端口。

步骤 1：创建 Tailscale 账户

访问 tailscale.com 创建免费账户。

步骤 2：生成认证密钥

  1. 前往 Settings → Keys
  2. 点击 Generate auth key
  3. 勾选 Reusable（用于多次部署）
  4. 复制密钥（以 tskey-auth- 开头）

步骤 3：启用 MagicDNS

在 Tailscale 管理控制台启用 MagicDNS，这样 hummingbot-api 可以通过名称解析。

方案一：一键安装 Condor（推荐）

这是最简单的安装方式，适合大多数用户。

步骤 1：打开终端

在 Mac/Linux 上打开终端，进入一个空文件夹（例如你的主文件夹，或先 cd Desktop）。

步骤 2：执行安装命令

步骤 3：按照提示完成配置

安装程序会首先询问你如何使用 Condor：

  1. Telegram 模式（推荐）：从手机控制的机器人
    • 需要提供 Telegram Bot Token
    • 需要提供你的 Telegram 用户 ID
  2. Local 模式：完全不使用 Telegram
    • 仪表板位于 http://localhost:8088
    • 已自动登录

安装程序还会询问是否在同一台机器上安装 Hummingbot API。

步骤 4：配置 Tailscale（如选择安装 API）

当安装 Hummingbot API 时，在询问是否启用 Tailscale 时回答 y，然后粘贴你的认证密钥。

创建 Telegram Bot

如果选择 Telegram 模式，需要：

  1. 在 Telegram 中打开 @BotFather
  2. 发送 /newbot 并按照提示命名你的机器人
  3. 复制 Bot Token（格式：123456789:ABCdefGHIjklMNOpqrsTUVwxyz）

获取用户 ID

  1. 在 Telegram 中打开 @userinfobot
  2. 发送 /start 获取你的用户 ID

API 连接地址

连接来源 API URL

检查 Telegram

打开 Telegram 中你的 Condor 机器人聊天。如果启动成功，管理员会收到类似 “Condor is online and ready.” 的消息。

查看日志

Condor 运行在名为 condor 的 tmux 会话中。要在不停止机器人的情况下分离：按 Ctrl+B，然后按 D。

控制命令

命令 说明
make run 在会话中启动 Condor
make stop 停止 Condor
make restart 重启 Condor
make status 显示运行状态
make run-fg 前台运行（调试启动错误时使用）
make doctor 重新验证依赖、配置、AI 模型等

Telegram 中的配置

在 Telegram 中使用以下命令配置你的交易栈：

  • /servers：Hummingbot API URL 和认证
  • /keys：交易所凭证
  • /gateway：DEX 设置
  • /start：设置快捷方式

Local 模式（无 Telegram）

在首次设置问题时回答 2) Local，Condor 将在完全没有 Telegram 机器人的情况下运行：

  • 无 token、无 /web 登录链接、无轮询
  • make run 启动进程，仪表板位于 http://localhost:8088，已自动登录
  • 其他功能完全相同——投资组合、机器人、代理、例程、交易
  • 原本发送到 Telegram 的通知会出现在仪表板的通知铃铛中

Local 模式没有登录。 任何能访问该端口的人都有完整的交易控制权。这就是为什么它只绑定 127.0.0.1——仪表板只能从运行它的机器访问，不能从局域网或互联网访问。

  2. 当询问 Use Tailscale for secure private networking? 时回答 y
  3. 粘贴你的认证密钥并部署：

在 Condor 机器上

  1. 安装 Tailscale 并登录同一账户
  2. 在 Telegram 中打开 /servers 并添加 API：
    • Host：hummingbot-api（MagicDNS 名称，不是公共 IP）
    • Port：8000
    • Username / Password：与 API .env 相同

验证连接

或

condor 和 hummingbot-api 都应显示为已连接的节点。

启用 Tailscale 时不要在你的公共防火墙上开放 8000 端口。 仅允许 SSH（22 端口）用于服务器管理。

常用命令

/portfolio 投资组合仪表板，包含 PNL 指标

/web Web 仪表板的限时链接
/admin 管理面板：用户和访问权限

常见问题排查

从 make doctor 开始——它会检查依赖、配置、AI 模型、端口暴露、Tailscale 和 API 连接性。

问题 解决方案
机器人无响应 检查 .env 中的 TELEGRAM_TOKEN 和 ADMIN_USER_ID
启动时退出：TELEGRAM_TOKEN is not set Telegram 模式需要 token。运行 make setup——或选择 Local 模式
Local 模式：仪表板无法从其他设备访问 这是预期行为——Local 模式绑定 127.0.0.1
访问待批准 管理员需通过 /config > Admin Panel 批准用户
命令失败 验证 Hummingbot API 正在运行
连接被拒绝 检查 /servers 中的服务器 host:port；当 API 在另一台机器上时使用 hummingbot-api（不是 localhost）
认证错误 验证服务器凭证与 API .env 匹配
DEX 功能不可用 确保 Gateway 已配置并运行
Tailscale：名称 hummingbot-api 不工作 在 Tailscale DNS 设置中启用 MagicDNS
Tailscale：无法访问 API 运行 tailscale status 确认两个节点已连接
Tailscale：认证密钥被拒绝 密钥必须以 tskey-auth- 开头，检查 Tailscale 管理中的过期时间
API 仍在公共 IP 上可访问 从云服务商防火墙/安全组中移除 8000 端口
