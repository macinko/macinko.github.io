Buzz 是由 Block（Jack Dorsey 所在公司）开源的人类与 AI

更新于2026-09-05|aitool
|总字数:1.5k|阅读时长:5分钟|浏览量:

Buzz 是由 Block（Jack Dorsey 所在公司）开源的人类与 AI Agent 协作工作空间。它基于 Nostr 协议，把聊天、代码仓库、工作流、Agent 参与统一在同一个可自托管的事件日志上：人和 Agent 使用相同的身份模型、权限与审计轨迹，真正“在同一个房间里一起工作”。

  • 官方仓库：https://github.com/block/buzz
  • 产品站：https://buzz.xyz
  • Stars：约 29.9k
  • 协议：Apache 2.0
  • 技术栈：Rust 中继（relay）+ Tauri/React 桌面端 + Flutter 移动端（进行中）

核心定位：可自托管的团队工作区，减少对 Slack + GitHub 的依赖，让 Agent 成为有独立密钥与权限的“队友”，而不是挂在某个人私聊里的机器人。

1. Buzz 是什么？

  • 表面：类似现代团队协作工具——频道、线程、私信、语音、媒体、搜索、审计日志。
  • 底层：一个 Nostr relay。每条消息、反应、工作流步骤、评审批准、Git 事件都是签名事件，人和进程使用同一套身份与审计模型。
  • 社区（Community）：用户通过 URL 进入的工作区。单中继部署下，relay URL 对应一个社区；托管多租户时仍按 URL 隔离。

Agent 不是“机器人集成”：它们有自己的加密身份、频道成员资格和审计轨迹，可以发帖、审代码、跑自动化、参与讨论，权限按身份约束，而不是简单的权限开关。

2. 主要能力

能力 说明
频道 / 线程 / DM 团队日常沟通
媒体与评论 可对特定帧留言
搜索与审计日志 对话、补丁、工作流、批准统一可搜
YAML 工作流 消息 / 反应 / 定时 / Webhook 触发
Git 事件（NIP-34） 补丁、仓库公告、状态
Git 托管后端 频道内托管仓库（仍在完善）
Agent 接入 Goose、Codex、Claude Code 等（经 ACP）
Desktop 客户端 Tauri + React
buzz-cli Agent 优先，JSON 进 / JSON 出

今日可用 vs 进行中：

  • ✅ 可用：中继、频道、线程、DM、画布、媒体、搜索、审计、桌面端、工作流、Git 事件与托管、Agent harness
  • 🚧 进行中：移动端、部分审批门禁、Huddle 生命周期等
  • 💭 愿景中：跨中继信任网络、完整推送等

3. 典型使用场景

  1. 事故记忆：凌晨问“以前见过这个错误吗？”Agent 从半年历史里拉出相关线程、根因与修复，整段对话留在频道。
  2. 分支即房间：开 feature 分支 → 自动出现频道 → 补丁、CI、Agent 初审、同事反应、合并决策都在同一房间。
  3. 发布自写：打 tag 触发工作流 → Agent 汇总 PR 写发布说明 → 人类 👍 → 发布，每步可签名、可搜索。

4. 快速开始

方式一：直接试用桌面端

从 Releases 下载：

平台 文件示例
macOS Apple Silicon Buzz_*_aarch64.dmg
macOS Intel Buzz_*_x64.dmg
Linux .AppImage / .deb
Windows *_x64-setup_alpha-unsigned.exe（可能触发 SmartScreen，选“仍要运行”）

默认连接 ws://localhost:3000。可设置环境变量 BUZZ_RELAY_URL，或在应用内切换中继。

也可在 buzz.xyz 使用 Block 托管服务。

方式二：从源码构建（开发 / 自托管）

依赖：Docker + Hermit（或手动准备 Rust 1.88+、Node 24+、pnpm 10+、just）

日常开发：

中继地址：ws://localhost:3000，桌面端会自动弹出。

分终端调试：

生产单机 / VPS：使用 deploy/compose/（Postgres、Redis、MinIO、可选 Caddy/TLS）。根目录 docker-compose.yml 仅用于日常开发。

Windows：Agent 的 shell 工具需要 bash，请安装 Git for Windows（自带 Git Bash）。也可通过 BUZZ_SHELL 指定其他 bash 兼容路径。

也可一键部署到 Railway 等平台（见 Block 工程博客相关文章）。

5. Agent 接入

  • buzz-cli：为 Agent 设计，JSON 输入输出，适合作为 LLM 工具调用。
  • buzz-acp：ACP 桥接，支持 Goose、Codex、Claude Code 等作为频道成员参与。
  • Agent 需配置 BUZZ_PRIVATE_KEY 等身份相关变量，以独立身份加入频道。

Agent 可以：

  • 搜索历史并贴证据
  • 开仓库、发补丁、做初审
  • 运行工作流、编辑画布
  • 创建频道、拉人进讨论 权限与人类队友类似，按身份与成员资格约束。

6. 架构概览

主要 crate 分组：

  • 协议核心：buzz-core、buzz-relay
  • 服务：buzz-db、buzz-auth、buzz-pubsub、buzz-search、buzz-audit
  • Agent 面：buzz-cli、buzz-acp、buzz-agent、buzz-workflow、buzz-persona
  • Git：git-sign-nostr、git-credential-nostr 等
  • 共享：buzz-sdk、buzz-media 等

完整说明见仓库 ARCHITECTURE.md。

7. 设计原则与愿景

  1. 自主权：自己跑中继，拥有域名与数据，密钥可带走。
  2. 开放：Apache 2.0、基于 Nostr、模型无关，不锁死在某一家。
  3. 单一上下文：对话、补丁、CI、评审、批准同一事件日志，搜索与审计一致。

愿景文档：VISION.md、VISION_SOVEREIGN.md、VISION_PROJECTS.md、VISION_AGENT.md。

8. 总结与推荐上手路径

Buzz 试图解决的是：工作被拆在聊天工具、代码托管、CI、各种 Agent 工具之间，上下文不断丢失；Agent 看不到完整现场就帮不上忙。它把人、Agent、对话、代码放在同一套密码学身份与事件日志里，适合想要自托管、可审计、Agent 原生协作的团队。

推荐路径：

  1. 从 Releases 安装桌面端，或打开 buzz.xyz 试用。
  2. 需要自控时：git clone → just setup && just build → just dev。
  3. 把 Goose / Codex / Claude Code 通过 ACP 加入频道，体验“Agent 当队友”。
  4. 尝试“功能分支 = 频道”，把补丁与讨论放在一起。
  5. 深入时阅读 ARCHITECTURE.md 与各 VISION 文档。
