教程｜Web 新站上线后，站内 Blog 到底怎么布局？从选词

更新于2026-09-23|toolssoftware
|总字数:5.5k|阅读时长:17分钟|浏览量:

新站做 Blog 布局的时候，我发现最容易让人卡住的，其实不是“不会写”。而是不知道第一篇该写什么。

网站刚上线，首页、功能页都已经有了，Blog 还是空的。打开 Semrush，一搜行业词，几百上千个关键词；再去看竞品，人家已经写了几百篇文章。

很多独立开发者都容易走两个极端。

一种是专挑搜索量大的词：“这个词一个月 10K，写它肯定有流量。” 另一种更省事：把竞品流量最高的十篇文章扔给 AI，“照着这些给我写十篇。”

虽然文章很快就有了，但几个月以后回来看，可能会发现一个很尴尬的问题：Blog 看起来很丰富，却没有形成任何搜索资产，没有为SEO带来任何贡献。

最可能出现的几个问题： 有的文章和产品几乎没关系，有的关键词根本打不动，有的页面 Google 都不知道它存在，还有几篇互相抢同一个关键词。

千万别觉得写博客，不就是找词、抄竞品框架、让 AI 扩成 2000 字。现在最不缺的就是“正确但没用”的文章，真正难的是：同一个关键词，你凭什么比已经排在前面的人多提供一点东西。 如果让我从 0 开始给一个新站布局 Blog，我不会先问：

今天写什么？

而是先把整个链路跑一遍：

产品 → 关键词池 → 搜索意图 → 竞品 → 内容地图 → 写作 → 内链 → 发布 → 收录 → GSC 数据 → 更新。

下面就把这套流程完整拆开。

01. 别急着找关键词，先搞清楚 Blog 要给产品带来什么

这是我觉得最容易被忽略的一步。很多人一说 Blog SEO，第一反应就是打开 Semrush、Ahrefs 开始找关键词。

但在找词之前，最好先把产品本身拆一遍。 拿 FeedLog 举个例子。它是一个 Feedback 产品，如果只从行业大类出发， 很容易找到： customer feedback user feedback feedback management customer feedback tools 这些词看起来都对。 但继续往产品场景拆，就会出现完全不同的东西： feedback widget website feedback widget how to collect customer feedback customer feedback system feedback board public roadmap changelog Canny alternatives

它们虽然都和 Feedback 有关，但**用户搜索这些词时，想要的东西并不一样。**搜索 feedback widget 的人，可能已经知道自己需要一个嵌入网站的反馈入口。 搜索 how to collect customer feedback 的人，还处于解决问题阶段。 搜索 Canny alternatives 的人，甚至已经用过或者了解某个产品，正在主动比较方案。

所以我会先做一件很简单的事情： 把产品拆成「核心品类—功能—使用场景—用户问题—竞品」几个方向。

比如：

核心品类：Customer Feedback ↓ 功能：Feedback Widget / Feedback Board / Roadmap / Changelog ↓ 场景：Collect Website Feedback / Manage Feature Requests ↓ 问题：How to Collect User Feedback / How to Prioritize Feedback ↓ 竞品：Canny / Featurebase / Usersnap……

为什么要先做这一步？

因为如果直接打开 Semrush 找词，你很容易被“有搜索量的词”带着走。customer experience 有量，employee feedback 也有量，甚至一些 AI、survey 相关词的数据可能更漂亮，但它们未必是这个产品真正想承接的用户。

产品拆解相当于先给选词画了一张地图。

之后看到一个关键词，你就可以反过来判断：它属于我的哪个品类？对应哪个功能或使用场景？用户搜完以后，我的产品能不能自然成为解决方案？

如果三个问题都很难回答，哪怕这个词有 10K 搜索量，也应该谨慎。

反过来，website feedback widget 可能只有几百搜索量，但它正好对应产品功能和真实使用场景，那它对新站的价值反而可能更高。

所以关键词工具真正解决的是“这个需求有没有人在搜、竞争大不大”，产品拆解解决的才是“这个需求值不值得我做”。

02. 先建一个 Keyword Pool，不要看到一个词就写一个

确定方向以后，我不会马上开始写。

先拉一个关键词池。

第一版不用特别精确，50～100 个词完全够用。这个阶段的目标不是确定标题，而是尽量把用户可能怎么搜索这个问题找全。

我一般会从几个地方一起找：

第一类是产品本身。

把首页、Feature、Use Case 里出现的核心概念拆出来。

第二类是 Google。

搜索框自动补全、People Also Ask、Related Searches，都是用户真实搜索表达的重要参考。

第三类是竞品。

用 Semrush/Ahrefs 看几个核心竞品有哪些页面正在拿自然搜索流量，尤其关注和自己产品高度相关的词。

第四类是社区。

Reddit、X、Indie Hackers 里搜用户怎么描述这个问题。

这一类经常会出现关键词工具里看不到的东西。

比如产品团队可能会说：

Feedback Management

但真实用户说的可能是：

We get feedback from email, Discord and X. How do you keep all of it organized?

后面这句话不一定直接变成关键词，但它会告诉你：用户真正困扰的可能不是“收集反馈”，而是“反馈散落在不同地方以后怎么整理”。

这会影响你后面的关键词、文章角度，甚至 Landing Page 文案。

所以 Keyword Pool 不应该只有：

Keyword,Volume,KD,feedback widget1,00035

我至少还会记录：

Keyword / Intent / Volume / KD / SERP Type / Product Relevance / Target Page / Priority

因为下一步真正重要的不是找词，而是删词。

03. 新站选词，我现在把“搜索量”放得越来越靠后

假设现在手里已经有 100 个词。怎么筛？

以前我也很容易先按 Volume 排序。

后来发现，这对新站特别容易产生误导。

一个月搜索 10K 的词，如果 SERP 前十全是行业巨头、媒体和十几年老站，对一个刚上线的网站来说，这个数字暂时没有太大意义。

反过来，一个只有 200 搜索量的词，如果搜索意图非常明确，而且和产品高度相关，可能更值得先做。

我现在大概按这个顺序判断：

产品相关性 → 搜索意图 → SERP 竞争 → 用户价值 → 内容延展性 → Volume / KD。

还是拿

FeedLog

举例。

customer feedback 很大，但它太宽了。

搜索结果可能包括定义、方法、案例、调查、工具等各种内容。

继续往下走：

customer feedback system

意图已经明显收窄。

再到：

website feedback widget

用户已经开始寻找一种具体的解决方案。

如果产品刚好有 Widget，那么后面的词虽然 Volume 可能更小，但每一个点击离产品都更近。

这也是为什么我越来越不喜欢只问：

“这个词搜索量多少？”

我更想知道：

“如果这个词只给我带来 100 个用户，他们是不是我真正想要的那 100 个？”

04. KD 只是参考，真正要看的东西在 Google 首页

这是新手选词特别容易踩的另一个坑。

看到：

Volume：500 KD：8

马上开写。

但 KD 本质上只是 SEO 工具根据自己的数据模型算出来的参考值。

最终决定你要做什么页面的，是搜索结果本身。

所以一个关键词进入候选以后，我一定会亲自 Google 一遍。

先别急着分析 DR、Backlinks，第一眼只看：

Google 到底在给用户什么？

比如你想写：website feedback widget

结果前十里大部分都是：

Best Website Feedback Tools Feedback Widget 产品页 How to Add a Feedback Widget 软件对比页

这时候已经得到一个非常重要的信息：

Google 对这个词的理解并不一定是“纯教程”。

如果前十几乎全是产品页，你却坚持写一篇 3000 字科普 Blog，本身就可能和搜索意图错位。

反过来，如果 Top 10 主要是：

“How to…” “Best…” “X vs Y…” “Complete Guide…”

Blog 才是更合理的内容形式。

所以我会在关键词表里专门留一列：

SERP Type。

Tool Page、Blog、Listicle、Comparison、UGC、Video……

先判断该不该写 Blog，再判断 Blog 应该怎么写。

这一小步，可以避免后面大量无效写作。

05. 竞品 Blog 最值得抄的，不是文章，是它的“内容地图”

接下来我才会真正进入竞品研究。

很多人研究竞品 Blog 的方式是：

找到对方流量最高的文章 → Copy URL → 丢给 AI → “参考这个结构帮我写一篇”。

这样确实很快。

但你只抄到了结果，没有看到对方为什么这么布局。

我更喜欢先把 3～5 个直接竞品过去半年到一年的 Blog 拉出来看一遍。

这时候先不要读文章正文。

先看：它最近一直在写什么？

比如一个 Feedback 产品连续更新：

  • Customer Feedback Forms
  • Customer Feedback Loop
  • Feedback Analysis
  • Customer Feedback Tools
  • How to Collect Feedback
  • How to Prioritize Feedback
  • Feature Request Management

如果只看单篇，它们就是七篇普通文章。

放在一起看，信息就完全不同了：

这个网站正在持续强化 Customer Feedback 这个主题。

这时候竞品真正告诉你的不是：

“你也写一篇 Customer Feedback Forms。”

而是：

“这个品类下面存在一整组值得建设的搜索需求。”

这就是 Topic Cluster。

新站尤其应该学这一点：内容主题布局。

与其今天写 AI，明天写 SEO，后天突然来一篇创业故事，不如围绕和产品最相关的一个主题，连续把十个问题讲透。

Google 更容易理解你的网站到底在讲什么，用户进入一篇文章以后，也有更多相关内容可以继续阅读。

06. 竞品写过 ≠ 你值得写，继续看它有没有真的拿到结果

这一步很重要。

竞品有 500 篇 Blog，并不意味着 500 篇都成功。

有些可能根本没有流量，有些是三年前的战略，有些只是为了品牌内容。

所以确定 Topic Cluster 以后，我会再回到 Semrush/Ahrefs，看具体页面。

主要看几个东西：

这个页面有没有自然流量？

主要排名词是什么？

一个页面覆盖了多少相关词？

排名是长期稳定还是最近突然上涨？

有没有明显的外链支撑？

这时候你才能慢慢区分：

这是竞品“写过的内容”。

还是：

这是已经被搜索结果验证过的内容。

这两件事完全不同。

因为竞品发布一篇文章，背后的原因可能有很多：为了补内容完整度、配合某次 Campaign、承接品牌传播，甚至只是三年前团队留下的一次尝试。

你看到它存在，不代表它有效。

但如果一篇文章已经持续获得自然流量，多个相关关键词进入 Top 10，甚至几年后还在更新，那它释放出来的信号就不一样了：

这个主题不仅有人写，而且真的有人搜，Google 也愿意持续把流量分给这类内容。

这时候再去研究它，价值就从：

“竞品写了什么？”

变成了：

“竞品已经帮我验证了什么？”

比如我发现三个 Feedback 竞品都写过 Customer Feedback Loop，这只能说明大家认为这个主题和产品相关。

但如果继续往下看，发现其中两篇几乎没有自然流量，而另一篇长期覆盖几十个相关关键词，主要流量还来自 customer feedback loop examples、how to create a customer feedback loop 这样的长尾词——

那真正值得拿走的信息就不是：“我也要写 Customer Feedback Loop。”

而是：“这个主题有搜索需求，而且用户更具体地在找 Examples 和 How to。”

这会直接影响后面的选词、标题和文章结构。

所以我看竞品内容通常是两步：

第一步看它在布局什么，找到 Topic Cluster；第二步看什么真的跑出来了，找到经过验证的搜索机会。

竞品的 Blog 列表告诉你它想做什么，流量和排名数据才告诉你什么真正跑通了。

07. 真正开始写之前，我会把 Google Top 5 全部拆一遍

关键词确定以后，还是不要马上让 AI 写。

比如最终决定做：

website feedback widget

我会把 Google Top 5 的页面全部打开。

不是为了看谁写了 2500 字、谁写了 3000 字。

而是回答三个问题：它们都写了什么？

如果 Top 5 都在解释：

What is a feedback widget Types of feedback widgets Best tools How to choose How to install

说明这些内容大概率属于这个搜索需求的“基本答案”。

你的文章完全不讲，可能会缺东西。

它们都没写什么？这一部分反而更重要。

有没有真实截图？有没有实际安装过程？价格是不是已经过期？有没有说明不同产品适合什么场景？有没有真正测试 Widget 在移动端的体验？有没有用户案例？

这才是你可以超过现有内容的地方。

用户看完以后，还会问什么？

继续去看 People Also Ask、Reddit、Quora、产品评论。

因为排名页面告诉你Google 当前认可什么，社区讨论则更容易告诉你用户还在困惑什么。

所以我现在对竞品内容的理解是：

竞品不是拿来改写的，而是拿来判断 Google 已经认可什么、用户还缺什么。

找到这个 Gap，再开始写。

08. AI 可以写，但别把“研究”也一起外包了

做到这里，Outline 基本已经自己长出来了。

这时候再用 AI，效率会高很多。

我会把前面整理出来的：

目标关键词、搜索意图、Top 5 共同结构、PAA、社区问题、自己产品案例、希望补充的 Gap，一起交给 AI。

然后让它帮助整理 Outline、补充遗漏、检查逻辑。

而不是只给一句：

Write a 2000-word SEO article about website feedback widgets.

这两种方式最后得到的文章，差距非常大。

因为 AI 很擅长把已有信息组织得更快，但如果前面的信息本身就是空的，它最容易生成的就是：

一篇结构正确、句子通顺、什么都讲了，但没有任何理由值得 Google 把它排到前面的文章。

所以我会把 AI 放在研究之后。

先有人做判断，再让 AI 放大效率。

09. 一篇 Blog 写完，不要只检查“关键词出现了几次”

文章写完以后，我会做一次发布前检查。

但现在已经很少纠结“关键词密度必须达到 1%”这种机械指标。

我更关心的是几个实际问题。

Title 有没有直接回答搜索需求？

用户搜索 website feedback widget，标题最好不要绕半天才告诉他文章讲什么。

H1/H2 有没有覆盖用户真正关心的问题？

不是为了塞关键词，而是帮助 Google 和用户理解页面结构。

关键词变体有没有自然出现？

比如主词是 website feedback widget，正文自然会涉及 feedback widget、website feedback、collect user feedback 等相关表达。

有没有自己的信息增量？

自己的截图、测试、数据、案例、观点、使用过程，哪怕只有一个，也比重新排列竞品的十个观点有价值。

最后还有一个特别容易忘的：这篇文章和产品是什么关系？

Blog 拿到排名不是终点。

用户读完以后，应该能自然进入相关 Feature Page、Use Case 或产品。

如果一篇文章带来了 1000 个 informational traffic，却没有任何路径进入产品，那它对业务的价值可能比想象中低。

10. 新文章发布后，先给它 5 条真正相关的内链

这一步我自己现在会特别重视。

很多人的发布流程是：

Publish → GSC → Request Indexing → 等。

但 Google 抓取网页，本身就高度依赖链接关系。

所以新 Blog 上线以后，我会先去找站内已经存在的相关页面。

比如发布了一篇：

How to Collect Customer Feedback

就去找之前的：

Customer Feedback System Feedback Widget Customer Feedback Loop 相关 Feature Page

在语义真正相关的位置给新文章加入口。

首页、Blog 分类页、Header、Footer 也可以承担结构性的发现入口，但正文里的上下文内链更能说明两个页面为什么相关。

我自己会把：

每个新页面至少找到 5 个合理的站内入口

当成一个操作习惯。

这里的重点不是“5”这个数字有什么神奇的 SEO 权重，而是逼自己检查：

这个页面有没有真正接入网站已有的内容网络。

如果一篇文章发布以后，整个网站没有任何页面指向它，它很容易变成一个孤岛页面。

11. 发布以后，才进入收录 SOP

做到这里再去 GSC。我一般会按这个顺序检查：

页面能否正常访问 → 没有误设 noindex → canonical 是否正确 → sitemap 是否包含页面 → 站内是否存在可抓取链接 → GSC URL Inspection。

然后再提交抓取。

这里一定要分清楚一件事：

Request Indexing ≠ 保证收录。

它只是告诉 Google：

“这里有个页面，你可以来看一下。”

Google 最后是否抓取、是否进入索引、多久进入索引，仍然取决于网站和页面本身的情况。

所以一篇文章几天没收录，不要每天机械地重复点 Request Indexing。

先检查页面是不是孤岛、内容是不是和站内大量页面高度重复、Googlebot 能不能访问、canonical 有没有指错。

收录不是按钮问题，很多时候是网站结构和页面质量问题。

12. 第一次发布不是结束，GSC 才开始告诉你这个词到底对不对

这一部分是我觉得整个流程里最有意思的地方。

前面做了那么多关键词研究，本质上都还是：你的判断。

文章上线以后，GSC 才开始给真实反馈。

假设你原来针对 A 关键词写了一篇文章。

两三周以后发现：

A：几乎没有曝光 B：300 次曝光，排名 16 C：150 次曝光，排名 11 D：80 次曝光，CTR 很低

这时候 B、C 反而值得重点研究。

因为 Google 已经在告诉你：

“我觉得你的页面和这些搜索需求有关。”

这时候可以重新打开 SERP。

看看排名 10～20 的原因是什么。

是不是缺了一段内容？

Title 和用户搜索意图不够一致？

是不是需要增加一个案例？

有没有相关页面可以补内链？

甚至你会发现，一个原本没有重点布局的长尾词，比主词更有机会。

这时候再更新文章。

所以我现在越来越不把 SEO 内容理解成：

选词 → 写文章 → 发布。

而是：

假设 → 发布 → 获取数据 → 修正 → 再验证。

第一版文章只是第一次下注，不是最终答案。

最后，把整个流程压缩成一张新站 Blog SOP

如果今天重新给我一个刚上线的网站，我不会第一天就开始疯狂写文章。

我会先拆产品，明确核心品类、功能、场景和用户问题；然后建立 50～100 个词的 Keyword Pool，再根据产品相关性、搜索意图、SERP 和竞争情况筛出第一批真正值得做的词。

接着选 3～5 个竞品，不只看它们“写了什么”，而是看它们围绕哪些主题持续布局、哪些页面真的拿到了搜索流量。

最终确定第一批 10～20 个内容以后，再逐个拆 Google Top 5，找到已有内容覆盖了什么、缺什么，然后开始写。

发布时做好内链和基础 On-page SEO，上线后检查 sitemap、GSC 和收录情况。

最后回到 GSC：

看真实 Query → 找到开始有曝光的词 → 更新内容 → 补内链 → 再观察。

整个过程其实就是一个循环：

产品 → 选词 → SERP → 竞品 → 内容 → 内链 → 收录 → 数据 → 更新。

做完第一轮以后，你才真正开始拥有属于自己网站的数据。

这时候第二批 Blog 写什么，就不应该再完全依赖 Semrush 告诉你。

因为 GSC 里已经开始出现一些东西：

Google 认为你的网站和什么有关，用户正在用什么词找到你，以及哪些页面已经离第一页不远。

新站 Blog 最难的其实就是第一轮。

第一轮是在没有自己数据的时候做判断。

第二轮开始，才是用真实数据修正判断。

所以新站 Blog 布局的目标，从来不是“尽快填满 Blog 页面”。

而是尽快跑通一次：

我认为用户会搜什么 → 我写出来 → Google 怎么理解 → 用户怎么搜索 → 我再改。

这个闭环一旦跑起来，后面的内容才会越写越准。 OK，Web 新站上线后，站内 Blog 到底怎么布局？从选词、竞品到收录完整拆解就到这里，觉得对你有用欢迎评论转发😃
