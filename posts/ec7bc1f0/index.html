Usque MASQUE Pro v6.7：Cloudflare WARP 可视化工具

更新于2026-09-13|webcdn
|总字数:1.5k|阅读时长:5分钟|浏览量:

📌 项目简介

Usque MASQUE Pro v6.7 是一个基于 Cloudflare WARP/MASQUE 的可视化工具，主要解决手动注册流程复杂、多客户端配置格式不统一等问题。它可在浏览器中完成一键注册、配置生成，并输出适用于 Clash/Mihomo、Shadowrocket、sing-box 等客户端的配置。

🚀 部署方式一：Cloudflare Pages（推荐）

这是官方最推荐的部署方式，尤其适合希望通过 Git 轻松管理版本和升级的用户。

方法 A：通过 GitHub 连接部署

第 1 步：准备 GitHub 仓库

  1. 在 GitHub 上新建一个仓库（例如 usque-custom-pro）。
  2. 将下载的项目文件解压，确保根目录包含 pages/ 和 workers/ 两个文件夹。
  3. 使用 Git 命令或 GitHub Desktop 将整个项目推送到你的 GitHub 仓库。

第 2 步：在 Cloudflare Pages 中连接 GitHub

  1. 登录 Cloudflare 控制台，进入 Workers & Pages。
  2. 点击 创建应用程序 → Pages → 连接到 Git。
  3. 选择你刚刚上传的 GitHub 仓库。
  4. 在“设置构建和部署”页面，进行如下关键配置：
    • 生产分支: main (或其他你推送的分支)
    • 框架预设: 无
    • 根目录: 务必填写 pages
    • 构建命令: 留空
    • 构建输出目录: 填写 . (一个点，表示根目录)
  5. 点击 保存并部署。

第 3 步：验证部署
部署完成后，Cloudflare 会提供一个 *.pages.dev 的域名。访问：

  • 首页: https://你的项目.pages.dev/，应看到项目界面。
  • API 健康检查: https://你的项目.pages.dev/api/health，正常应返回 JSON: {"ok":true,"service":"usque-register-relay","worker":"running"}。这表示 API 路由工作正常。

方法 B：直接上传文件（无 Git）

如果不使用 Git，可以在 Pages 创建时选择“直接上传”。

  1. 在本地进入项目中的 pages/ 文件夹。
  2. 选中该文件夹内的 所有文件 (index.html, _worker.js, _routes.json 等)。
  3. 将它们直接拖拽上传。注意：不要上传 pages 文件夹本身，必须让这些文件位于网站的根目录。

📖 首次使用教程

无论用哪种方式部署，访问你的项目域名后，按以下步骤操作。

第 1 步：一键注册

  1. 点击网页上的 “注册 Usque / WARP” 按钮。
  2. 浏览器会本地生成密钥，并与 Cloudflare API 交互完成注册。
  3. 重要：注册成功后，立刻点击 下载 usque-config.json。此文件包含你的核心凭证，务必妥善保管。

第 2 步：后续使用（导入配置）
以后每次使用，都不需要重新注册。

  1. 打开项目网页，找到导入区域。
  2. 上传你之前保存的 usque-config.json 文件。
  3. 根据需要调整参数（节点数量、传输协议、分流规则等）。
  4. 点击 “应用设置并重新生成”。

🔧 客户端配置生成示例

导入配置后，你可以为不同客户端生成配置。

生成 Clash/Mihomo 配置

  1. 在“输出格式”中选择 Clash / Mihomo。
  2. 参考设置：节点数量选 13 或 32，传输协议选 QUIC/H3，规则模式选 完整智能分流。
  3. 点击生成并下载 .yaml 文件。
  4. 在 Clash Verge Rev 等客户端中，导入此本地配置文件并启用。

生成其他格式

  • Shadowrocket：选择对应格式，生成可直接导入的配置。
  • sing-box：生成配置后，需先启动 Usque 的 SOCKS 代理（见下文），再使用 sing-box 运行配置。
  • VLESS 本地桥接：此功能生成的是 127.0.0.1:2081 的本地 VLESS 节点，并非远程 VLESS 服务器，需配合本地 Usque 和 sing-box 服务一起使用。

⚠️ 重要须知与常见问题

在使用前，有几个核心概念需要了解：

  1. 节点数量 ≠ 独立出口：生成的多个节点，是基于同一套凭证、使用不同的入口（Endpoint）和端口组合。最终出口 IP 可能相同或相似。
  2. 出口国家不可强制指定：修改入口不能保证将出口强制变更为特定国家。项目中的“出口检测”功能是检测现有节点的真实出口，并进行优选。
  3. ChatGPT 策略：如果 ChatGPT 无法访问，项目默认的策略是将其设为 DIRECT（直连），以避免共享 WARP 出口被限制。你也可以在设置中切换为 AI 自动选择 等其他策略。
  4. VLESS 地址为 127.0.0.1：这是正常的，因为它是本地桥接。你必须先通过命令行启动 Usque 的 SOCKS 服务（例如 usque.exe -c config.json socks -b 127.0.0.1 -p 1080），再启动 sing-box，VLESS 节点才可用。
  5. 安全提醒：usque-config.json 包含你的私钥和令牌，切勿上传至任何公开场所。

💎 总结

对于多数用户，推荐通过 GitHub + Cloudflare Pages 的方式部署，操作简单且便于更新。部署成功后，整个使用流程可以简化为：打开网页 → 导入 config.json → 调整设置 → 下载客户端配置 → 导入使用。

如果在部署中遇到 /api/health 无法访问，通常是因为 Pages 的“根目录”或“构建输出目录”设置不正确，请仔细检查是否指向了 pages/ 文件夹及其内部文件的正确位置。
