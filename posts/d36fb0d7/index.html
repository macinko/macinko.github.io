装上这个Skill，让你的WorkBuddy正常访问github

更新于2026-09-05|aiagent
|总字数:1.6k|阅读时长:5分钟|浏览量:

一直以来，很多小伙伴在使用AI工具上，都会遇到一个难题或者卡点，那就是本地电脑的网络无法正常访问github。

这不仅说是使用浏览器无法正常访问github的网站，还包括让一些AI Agent软件去github上下载安装Skill。

比如你让WorkBuddy去安装一个某博主分享的Skill，地址就是github的，结果WorkBuddy搞了半天最后告诉你，无法正常访问，网络有问题，安装不了。

而众所周知，不少优秀的AI软件都是开源后，放在github上的，当然还有大量优秀的Skill技能，文档、素材啥的。

有些有电脑使用基础的小伙伴可能会说，这还不简单么，开个神秘力量，直接搞定。或者Windows在微软的应用商店，下载一个Watt Toolkit。又或者让WorkBuddy去修改hosts文件。

第一种方式老马是一直不怎么推荐小白用户去弄的，首先是有门槛，其次不合法。第二种方式是老马经常让小伙伴在公众号回复github进行获取的，就是这个Watt Toolkit。

但是微软应用商店在国内的某些网络环境下，还是会抽风，导致无法正常下载软件。而第三种方式修改hosts文件，WorkBuddy没有很好的指引又可能会瞎搞。

大家应该知道，Windows的电脑系统环境，每个人的都不一样，复杂性难以想象。种种原因限制之下，老马觉得还是搞一个全自动的github访问Skill，一键帮小白用户设置或者修复好github访问。

这个Skill做了四层的兜底设计，你让WorkBuddy去安装设置的过程中，它会不断地去测试和配置，需要耗费的时间会长一些。

所以请耐心等待，可以不用管它，你要处理别的任务，新建一个新的WorkBuddy任务去处理就行。对了，Mac系统在期间会要求你输入开机密码，这是为了获取授权去修改hosts文件。

01 · FOUR-LAYER FALLBACK
01 · 四层备用方案

github访问Skill的四层兜底设计如下：

1、hosts 智能修复：修复浏览器/Agent 直连不通的域名

三源 IP 候选池（GitHub520 源 + 阿里/DNSPod DoH + 已知网段），逐条实测，每域名最多写 3 个备胎 IP。

2、镜像下载加速：修复直连彻底救不活时的下载

6 家公益镜像竞速，谁活着用谁，自动故障切换，git 配置 insteadOf 让 git无感走镜像。

3、SSH-over-443：修复22 端口被封时的 git 通道

hosts 固定

ssh.github.com

+ git 走 443 端口 SSH，几乎打不死。

4、诚实底牌：实在修复不了如实告知原因

说清哪条救不了、为什么 + 两条出路指引（镜像手动拼接法 / Watt Toolkit），只指引不代装，绝不假装修复成功

其它更多的介绍就不给大家贴出来了，这个Skill还解决了有些Agent的沙箱限制问题。因为像WorkBuddy这类AI办公Agent，跑任务时会使用沙箱，这样会出现网络隔离后的本地代理无法连通github。

02 · INSTALL & VERIFY
02 · 安装并验证

安装该Skill非常简单，你只需在WorkBuddy新建一个任务，默认权限改成允许完全访问，模型的话老马推荐使用GLM-5.3-Flash，这个模型不仅消耗积分少，活干的还好。

然后把下面的提示词直接粘贴在对话框里面，发送给WorkBuddy去安装设置就可以了：

整个安装和设置的过程需要一点时间，刚才也说过了，因为Skill会去跑四层的兜底流程，遇到有些网络波动的情况下，还会多次尝试去设置。

老马自己是Mac系统，已经完全跑通设置，以后就可以不需要任何工具和设置，直接随时访问github了，包括老马电脑上的WorkBuddy也是如此，它也能丝滑地随意安装各种github上的软件或者Skill。

为了保证Windows系统的小伙伴也能正常安装使用该Skill，老马还在群里找了几个人一起参与了测试，他们的系统覆盖了Windows10和11，基本都能顺利跑通设置成功：

上图中暴露出来一个Windows脚本的bug，老马也一并在最新版本的Skill中修复了。

当WorkBuddy已经告诉你github访问的Skill已经安装设置成功后，你就可以打开电脑的浏览器，访问一下github.com，看看能不能正常打开。

能正常打开了，你就再让WorkBuddy随便去安装一个github上的开源Skill，网址得是github的地址。

比如下面老马是让参与测试的小伙伴去安装归藏老师的PPT Skill，结果显示安装成功，说明Agent端的github访问也搞定了：

在此也非常感谢参与Skill测试的几位小伙伴，为验证github访问Skill的可用性及兼容性提供了很给力的帮助。这也确保了该Skill，可以正常给到大部分人去使用了。

有一说一，Skill是没有完美的，因为每个人使用的Agent软件不一样，大模型不一样，系统环境不一样，再加上有些小伙伴电脑上还安装了什么360安全卫士，火绒等安全防火墙软件。

在Skill实际的安装过程中，因为是需要去修改系统的hosts文件，这些安全防火墙设置就可能出来拦截了，提示这儿那的危险啥的。Skill本身没有安全危险，遇到这种情况请记得都要点击允许操作。

如果你在使用github访问Skill的过程中，还是遇到了老马没有遇到过的bug问题。或者Skill已经跑完了四层兜底流程，告诉你github访问设置修改失败的，记得截图错误原因，在评论区回复告诉老马。

老马会根据你的报错截图，进一步测试完善该Skill，再给你新的版本去安装设置看看能不能跑通。最后当然还是希望大家都能通过github这样的开源社区，自然顺畅的享受各种开源福利。
