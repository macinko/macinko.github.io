马斯克的 Grok Bot：为 AI 准备的 Mac mini 还要买吗

更新于2026-09-05|aiagent
|总字数:2.9k|阅读时长:8分钟|浏览量:

每天刷 X 找选题，最耗时间的常常是前半段：翻消息、找原文、确认是不是旧闻、把链接整理好。真正动笔时，精力已经用掉一半。

我看了成峰在「AI产品自由」发布的

这篇 Grok Bot 介绍

。里面一个思路很值得展开：把适合重复执行的工作放到云端，自己的电脑留给剪辑、设计和验收。

所以这篇攻略只解决一件事：搭一个 Grok Bot 选题助手，让它交来一份带来源、能检查、值得继续写的简报。

说明：本文依据截至 2026 年 9 月 4 日的公开公告与官方文档整理。下面的选题流程和提示词是我设计的起步方案，不是已经连续运行多天的实测报告。

一、Grok Bot 到底是什么？先想象一个云端工位

这里说的 Grok Bot，是可以接任务、使用工具和云端电脑的助手产品。它与

grok.com

或手机里的普通 Grok 聊天入口有区别。

官方产品说明

你可以给它一个名字和长期职责，例如「选题研究员」。以后就持续把这一类工作交给它。它可以在云端打开网页、处理文件、执行任务，再把结果交回对话。

官方概览

值得理解的是工作在哪里执行。云端任务已启动后，合上自己的电脑通常不会把任务一起关掉；不过登录过期、网站验证、用量不足等情况仍可能让它停下来。

后台运行与用量说明

再记住一个细节：同一账号的多个 Bot，各有自己的操作屏幕，但共享一台云端电脑的文件、浏览器登录和资源。可以把它想成一间办公室里的不同工位，不能当成互相隔离的电脑。

电脑与应用文档

看懂这张图，就不容易把「多个 Bot」误解成「多台独立服务器」。

二、先确认能用，再考虑付费

从

Grok Bot 官方入口

开始。桌面端提供 macOS、Windows 和 Linux 版本，不需要专门买一台 Mac。

截至本文核查时间，8 月 26 日的

官方扩展开放公告

列出了 SuperGrok、Plus、Heavy，以及 Cursor Pro、Pro+、Ultra 和 Teams Standard／Premium。Bot 用量与原有 Grok、Cursor 用量单独计算。

**但官方页面存在不同步：**9 月 2 日更新的入门页和 FAQ，套餐清单仍没有列出部分基础档。因此先查看自己登录后的实际权益和额度；如果入口没有开放，再核对支持说明，不要只凭一篇教程直接升级套餐。

「包含使用额度」也不等于无限使用。后台任务仍会消耗 Bot 额度；是否能额外付费、花费上限多少，应以账号页面显示为准。

三、创建第一个 Bot：名字好听，不如职责清楚

下载对应系统的客户端，安装后点 Get started，按浏览器提示完成账号登录并返回客户端。官方流程使用 Cursor 账号认证；首次配置云电脑可能需要等待。

安装与首次登录步骤

首次引导可选择 Create your own。已经进入主界面时，可以从 New → New chat → Create new agent 创建，再到 Edit Profile 修改名字和职责。不同版本的界面文字可能略有差别。

创建与管理 Bot

我建议先建一个，命名为「选题研究员」。简介负责写长期规则，每次聊天再给它当天的任务。下面这段可作为简介的起点：

先别急着接入所有工具。如果任务只用公开网页，可以从公开资料开始；如果需要 X 搜索、时间线等能力，再到 Settings → Plugins 找到 X 连接器并授权。

官方在 8 月 29 日说明了 X 连接器的搜索、时间线和消息聚合能力，并为付费 Bot 用户提供起步 API 额度；这不是无限调用承诺。

Grok Bot 与 X 集成说明

遇到登录或验证码，打开 Agent Computer，自己接管完成，再把控制交回。密码和验证码不要写进普通聊天。

四、第一份作业：先交 5 个选题，不要一上来包办账号

第一轮的目标很小：确认它能找到可信的新消息，并按你需要的格式交付。把下面的任务发给「选题研究员」：

收到结果后，花几分钟检查三个地方：链接能不能打开；事件是不是这次真的发生；所谓「上线」到底是全量开放、部分用户可用，还是仅仅预告。

例如，一个产品今天发了介绍文章，却要下个月才开放。简报里就应该写「今天公布，下月计划开放」，不能被压缩成「今天已上线」。这是我会优先检查的选题错误。

如果它找不齐 5 条，交 3 条可信消息也比凑 5 条好。没有连接器、网页看不到全文、时间范围受限，都应该出现在结果里。

五、稳定后再加人：研究、核查、编辑，分别交付

当一个 Bot 已经能把小任务做好，再考虑拆分职责。桌面端可从 New → New chat 选择 2—6 个 Bot 建群；它们可以在群里协作和交接。

官方协作说明

这里可以建三个角色：研究员收集候选消息；核查员对照原始公告检查日期、开放范围和存疑点；编辑把核查后的材料整理成前 5 个选题。

这是一套建议分工，不是系统自带的万能编辑部。给每一棒明确的交付物，才更容易验收。

群聊里先说明顺序：研究员交候选清单后交给核查员；核查员标明「已确认／待确认」后交给编辑；编辑只提交简报，不直接发布。需要接手的人和材料都写清楚。

同一条消息被三个 Bot 重复一遍，仍然只有一个来源。核查的价值在于打开原始证据，不在于多几个 Bot 表示同意。

六、从每天手动发消息，变成每天定时交作业

这里有两个英文词，记住就够了：Skill 是「这件事怎么做」的操作方法；Routine 是「什么时候做」的时间表。

一次任务通过验收后，把方法保存为 Skill，再让负责的 Bot 创建 Routine。官方也建议先跑通单次任务，再做自动化。

技能与定时任务说明

顺序是：做对一次 → 保存做法 → 设置时间 → 检查试跑。

确认第一份简报合格后，可以把下面这段发给同一个 Bot：

不要只看它回复「设置好了」。检查下次运行时间是否真的是北京时间早上 8 点，并跑一次 Test run。之后到 View conversation details → Routines 查看运行记录、暂停或修改任务。

这是减少每天重复交代的办法；选题判断和最后发布，仍留给自己。

七、卡住时先看这几处

**一直显示忙：**打开电脑视图，检查是否在等登录、网页响应或你批准某个动作。需要停止当前工作时，直接发「Stop now」。

**定时简报没有来：**检查 Routine 是否启用、时区是否正确、连接器授权有没有过期，以及用量是否已经耗尽；再看最近一次运行记录。

**云电脑连不上：**先重试、重启应用，再看界面提供的恢复选项。不要一开始就 Reset Agent Computer，重置可能丢失近期未同步的工作。以上对应

八、它能不能让你少买一台电脑？看你缺的是什么

原文提到可以先缓缓购买 Mac mini。我的理解是：如果你买电脑主要为了让自动化任务长期挂着，确实值得先测试云端方案。

但如果瓶颈是剪视频、修大图、处理本地素材，或者必须在自己设备上运行特定软件，Grok Bot 并不能据此替代那台电脑。云端费用、可用额度、网站兼容性，也需要放进自己的账里一起算。

我会先用一个小目标判断它有没有价值：连续几天，早上打开对话时，是否真的少做了一轮找链接、辨旧闻和整理材料的工作。

让 Bot 先把材料准备好，把精力留给选什么、怎么讲、值不值得发。这份攻略，就从第一份可以检查的简报开始。
