甲骨文云永久免费 4 核 24G VPS 服务器申请实战教程

更新于2026-09-13|globalvps
|总字数:3.7k|阅读时长:12分钟|浏览量:

甲骨文云的 Always Free 还是很香：Arm A1 免费额度可以做到 4 核 24G 内存，再配 200G 免费块存储，拿来跑轻量服务、面板、AI 辅助工具、测试环境都够用。

我这次把注册、升级、开机、SSH、放行端口、安装 1Panel 和保活注意事项整理成一篇。今天不讲玄学，讲哪些细节真的会影响通过率。

先说结论

资源Always Free 额度我的理解Ampere A1 计算每月 3000 OCPU 小时等价 4 OCPU 一直开Ampere A1 内存每月 18000 GB 小时等价 24GB 内存一直开Block Volume总计 200GB系统盘和数据盘共享出站流量官方网络免费额度内使用个人服务基本够用，重流量业务别乱跑。

也就是说，常说的“甲骨文永久免费 4 核 24G”，本质不是一个固定套餐，而是免费额度刚好能组合出一台：

4 OCPU 24 GB RAM Ubuntu Arm Ampere A1
4 个 CPU 核心 24GB 内存 Ubuntu 臂安培 A1

为什么说它值得折腾

市面上便宜 VPS 很多，但 4 核 24G 这个规格，正常买不会太便宜。

Oracle 这个免费资源适合干这些事：

  • 跑 1Panel、Docker、Nginx、数据库测试环境。
  • 自建一些轻量工具，比如 RSS、uptime、个人 API、Webhook 服务。
  • 给独立开发项目做 staging 环境。
  • 跑一些 Arm 兼容的软件和自动化任务。

不适合干这些事：

  • 大流量下载、BT、采集、扫端口。
  • 挖矿、刷量、垃圾营销。
  • 长期占资源但没有真实业务。
  • 对稳定性要求极高的生产主站。

我的判断是：它适合做“个人生产力服务器”，不适合当灰色项目机器。甲骨文风控不弱，别把免费资源当无限资源。

我的实操环境

这部分是我的记录模板，你可以按自己的情况替换。

  • 注册时间：2026-04
  • 注册地区：中国
  • 注册网络：手机流量/宽带
  • 邮箱：163 / QQ / Gmail 均可，（我用的163）
  • 银行卡：支持外币验证的 Visa / Mastercard / American Express
  • 目标区域：新加坡
  • 最终实例：Ubuntu + Ampere A1 + 4 OCPU + 24GB RAM
    最终配置：Ubuntu 操作系统，处理器为 Ampere A1 系列，配备 4 个 CPU 核心，内存为 24GB。
  • 成本结果：注册验证通常有小额预授权(用的是运通单标卡）；升级 PAYG 可能出现更高额度预授权，正常会释放，账单以后台为准

我建议你把这些信息单独记下来。Oracle 注册失败时，很多人会一直换邮箱、换地址、换卡，最后自己都不知道是哪一步触发了风控。

注册前的准备

\1. 网络环境尽量干净

注册 Oracle Cloud，不建议用机房代理、机场节点、共享代理。

更稳的选择：

  • 家庭宽带。
  • 手机 4G/5G 流量。

如果你用手机流量，可以先开关飞行模式换一个出口 IP，再查一下 IP 风险。

常用检测：

https://ping0.cc

https://scamalytics.com

https://ipinfo.io

不是说分数好就一定过，但机房 IP、黑名单 IP、代理特征明显的 IP，失败率会高很多。

\2. 邮箱不要来回换

我不建议一失败就换邮箱。

如果你的 IP、姓名、账单地址、卡都不稳定，换邮箱也没意义。邮箱用国内 163、QQ，或者 Gmail 都可以。关键是这个邮箱最好干净、常用、能稳定收验证码。

\3. 信用卡信息要和账单地址一致

这是很多人忽略的点。

Oracle 注册会验证支付方式。官方明确说不接受虚拟卡、一次性卡、预付卡，借记卡也可能不稳定。更推荐真实信用卡，支持 Visa / Mastercard / American Express。

我建议你先打开银行 App，导出或查看最近一期账单，然后按账单上的信息填写：

  • 姓名。
  • 国家/地区。
  • 省市。
  • 详细地址。
  • 邮编。
  • 手机号。

尤其是邮编。很多人地址写得差不多，但邮编和银行账单不一致，卡验证就容易失败。

我的填写建议：

  • 姓名可以用中文，也可以用拼音，优先和银行账单一致。
  • 地址不要自由发挥，照账单抄。
  • 手机号用自己真实手机号，能接短信即可。
  • 不要频繁提交，多次失败后先停下来。

如果还没信用卡的小伙伴可以参考一下。

学习AI之搞定支付|为什么你需要一张国际信用卡及申请指南

有不少朋友过来问我有没有用过ChatGPT、Claude、Gemini的工具，我直接告诉他怎么就能快速开通体验，但是不少人表示自己还没有一张外币卡（Visa、万事达、运通卡），那就差这一步了，可能离最先进的AI模型只差一张支…

第一步：注册 Oracle Cloud 账号

进入官网：

https://www.oracle.com/cloud/free/

点击开始免费使用，然后按页面填写：

  1. 邮箱。
  2. 国家/地区。
  3. 姓名。
  4. 手机号。
  5. 账号名称。
  6. Home Region。
  7. 信用卡验证。

这里最关键的是 Home Region。

Oracle 文档里写得很清楚：Always Free 资源和你的 home region 绑定。你注册时选错区域，后面不能随便切过去重新开免费机。

所以注册前先想清楚：

  • 想访问亚洲业务，可以考虑新加坡、日本、韩国。
  • 想做欧美服务，可以考虑美国区域。
  • 热门区域资源紧张，新加坡、东京经常容量不足。
  • 冷门区域可能更容易开机，但网络延迟不一定适合你。

我个人更看重“能开出来”，其次才是延迟。如果你死盯新加坡，可能账号注册成功了，但 A1 一直提示没容量。

第二步：注册失败时怎么判断

Oracle 注册失败常见不是一句中文提示，而是各种验证失败、支付失败、页面报错。

我一般按这个顺序排查：

问题优先检查卡无法验证是否虚拟卡、预付卡、余额不足、账单地址不一致页面反复失败IP 是否代理/机房、浏览器是否开了插件手机验证失败手机号国家码、短信拦截、短时间重试太多注册后进不去邮箱验证、账号名、地区是否填错

不要一失败就连续猛点提交。

更稳的做法是：

  1. 换回干净网络。
  2. 清理浏览器缓存，或者换无痕模式。
  3. 对照银行账单重新检查地址和邮编。
  4. 等一天再试。

连续失败太多次，后面就更像玄学了。

第三步：注册成功后先不要急着开机器

注册成功后，先确认两件事：

Billing -> Payment method Identity -> Domains / Users

看支付方式是否正常，账号状态是否正常。

然后进入 Compute 创建实例：

Compute -> Instances -> Create instance

镜像建议：

  • Ubuntu 22.04 / 24.04。
  • Oracle Linux 也可以，但新手用 Ubuntu 更顺手。

Shape 选择：

Ampere VM.Standard.A1.Flex

配置：

OCPU: 4 Memory: 24 GB Boot volume: 默认或按需调整，注意总免费块存储 200GB

页面上一定要看到类似：

Always Free-eligible

没有这个标记，就不要乱点创建。付费资源真的会出账单。

第四步：容量不足怎么办

热门区最常见的报错就是资源不足。

免费账号开 A1，经常遇到：

Out of host capacity

或者页面提示当前可用域没有容量。

可以尝试：

  • 换 Availability Domain。
  • 换 Fault Domain。
  • 降低规格，比如先开 1C6G，后面再扩。
  • 凌晨或工作日低峰期再试。
  • 换冷门 home region 重新注册一个新账号，但这条成本最高。

如果你已经注册成功，但一直开不出来，我更建议考虑升级 PAYG。

第五步：是否要升级 PAYG

PAYG 就是 Pay As You Go，现收现付。

我这次的关键选择就是：注册成功后升级 PAYG。升级后资源池优先级通常会比纯免费账号好很多，开 A1 成功率明显提高。

但这里必须说清楚：

  • PAYG 不是永久免费账号。
  • 你用了 Always Free 额度内的资源，仍然可以是 0 元。
  • 你一旦创建了不带 Always Free-eligible 的资源，就可能收费。
  • 升级时可能会有较高金额的预授权或验证，最后以 Oracle 后台和银行卡账单为准。
  • 升级后一般不要指望轻松退回纯免费账号。

我的建议：

如果你只是想随便玩玩，不升级也行。

如果你真的需要这台 4C24G 长期开服务，并且愿意认真检查账单，PAYG 更现实。

升级路径是：

Account Management -> Upgrade and Manage Payment -> Upgrade

升级后收到类似订阅更新邮件，再回去创建 A1 实例。

邮件主题可能类似：

Oracle Cloud Services: your subscription(s) has been updated

第六步：SSH 连接服务器

创建实例时，Oracle 会让你配置 SSH Key。

我建议新手直接下载系统生成的私钥文件，比如：

ssh-key-2026-05-25.key

本地执行：

chmod 600 ssh-key-2026-05-25.key ssh -i ssh-key-2026-05-25.key ubuntu@你的公网IP

如果镜像是 Oracle Linux，默认用户名可能是：

opc

Ubuntu 常见用户名是：

ubuntu

登录进去后先切 root：

sudo -i

再更新系统：

apt update && apt upgrade -y apt install -y curl wget vim git unzip

不建议一上来就改密码登录。密钥登录更安全，后续熟悉了再按自己的安全策略调整。

第七步：放行端口

很多人实例创建成功，脚本也安装成功，但浏览器就是打不开。

原因通常是两层防火墙都没放行。

\1. Oracle 控制台安全列表

进入：

Virtual Cloud Networks -> Security Lists -> Ingress Rules

添加入站规则，例如：

端口用途22SSH80HTTP443HTTPS8888面板端口，按你的实际端口改

来源可以先用：

0.0.0.0/0

但正式使用时，管理面板端口最好限制为自己的固定 IP，或者套 Cloudflare / VPN，不要裸奔。

\2. 系统防火墙

Ubuntu 可以先看：

ufw status

如果只是个人测试机，可以先放行需要的端口：

ufw allow 22/tcp ufw allow 80/tcp ufw allow 443/tcp ufw allow 8888/tcp

如果系统里还有 iptables 规则，需要一起检查：

iptables -L -n

不要一上来就清空所有规则。能按端口放行就按端口放行。

第八步：安装 1Panel

我这台机器准备先装 1Panel，后面跑 Docker 服务比较省心。

安装时重点记住这几个信息：

  • 安装目录：默认 /opt/1panel 就行。
  • 面板端口：可以自定义，比如 8888。
  • 安全入口：不要用默认值，改一个自己能记住的。
  • 用户名和密码：保存到密码管理器。

安装完成后，浏览器访问：

http://你的公网IP:面板端口/安全入口

如果打不开，先回到上一节检查 Oracle 安全列表和系统防火墙。

第九步：保活和回收规则

Oracle 官方确实有闲置回收规则。Always Free 实例如果长期低使用率，可能被标记为 idle 并回收。

官方对 idle compute 的判断会看这些指标：

  • CPU 利用率长期很低。
  • 网络利用率长期很低。
  • 内存利用率长期很低。

网上有很多所谓“保活脚本”，但我不建议为了保活故意空转 CPU。这样既没意义，也容易把账号搞得更危险，后面我还会讲一些关于服务器上的一些内容。

例如最近我已经讲codex、openclaw安装到这台服务器上了。

Linux 服务器上 Codex + 手机 Remote Control 全流程指南（含 OpenClaw Token 失效修复）

最近 OpenAI 推出了 Codex Remote Control，可以直接通过手机 ChatGPT App 远程控制服务器上的 Codex CLI。 经过我九九八十一次实验终于成功了，下面有图有真相 我实际在： - Linux 云服务器 - Docker - 1Panel -…

更靠谱的方式是让机器跑真实服务：

  • 1Panel + Docker。
  • Uptime Kuma。
  • RSSHub。
  • 个人 API。
  • OpenClaw / AI 辅助服务。
  • 备份脚本、Webhook、监控服务。

简单说：别让机器长期空着，也别让它无意义满载。

常见问题

Q：甲骨文 4 核 24G 真的是永久免费吗？ A：Always Free 额度内可以长期免费，但不是所有资源都免费。创建实例时必须确认 Always Free-eligible，并定期看账单。

Q：为什么我注册成功了，但是开不出 A1？ A：大概率是 home region 容量不足。可以换 AD/FD、降低规格、换时间段试，或者升级 PAYG。

Q：升级 PAYG 后还免费吗？ A：只要资源仍在 Always Free 范围内，理论上可以 0 账单。但 PAYG 账号能创建付费资源，自己要更谨慎。

Q：能不能用虚拟卡注册？ A：不建议。Oracle 官方说明不接受虚拟卡、一次性卡、预付卡。真实信用卡成功率更高。

Q：A1 是 Arm 架构，会不会软件不兼容？ A：会有这个问题。常见 Docker 镜像要确认支持 linux/arm64。如果软件只有 x86 镜像，A1 就不适合。

我的建议

如果你第一次申请 Oracle Cloud，不要把它当成“点几下就送服务器”。

更稳的流程是：

  1. 先准备干净网络。
  2. 对照银行账单填写真实地址。
  3. 选择一个你能接受延迟、也相对容易开机的 home region。
  4. 注册成功后先检查账号和支付方式。
  5. 开 A1 时只选 Always Free-eligible。
  6. 容量不足再考虑 PAYG，不要盲目升级。
  7. 建好机器后马上配置 SSH、安全列表、防火墙和账单告警。

最后一定要开预算提醒。

路径大概是：

Billing & Cost Management -> Budgets -> Create Budget

哪怕你只设 1 美元提醒，也比月底发现出账单强。

总结

甲骨文永久免费 4 核 24G VPS，核心不是“白嫖玄学”，而是三个点：

  1. 注册资料和支付验证要干净一致。
  2. Home Region 选对，因为免费资源跟区域绑定。
  3. 创建资源时只碰 Always Free-eligible。

我会把它当一台长期个人工具机：跑面板、监控、小服务、测试环境。不要把它当无限流量机器，也不要拿来做高风险业务。
