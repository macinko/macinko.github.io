手把手保姆级教程教你如何使用 Hermes Agent 自动管理 X 账号

更新于2026-09-13|aiagent
|总字数:2.9k|阅读时长:9分钟|浏览量:

如何使用 Hermes 自动管理 X

做社交媒体内容，经常会在写稿、改稿、切换账号和发布之间来回折腾。接入 Hermes 后，可以直接把想法发给它，在聊天里一起调整措辞和排版，确认后再让它用指定的 X 账号发布。需要另一个账号转发，也可以接着交代，不必自己来回切换。这只是最常见简单的用法，还可以有更多的玩法。

我用 Hermes 管理多个 X 账号时，会把应用配置和账号分开写清楚。配置脚本让 Hermes 准备，密钥和浏览器授权由我自己完成，后面的读取、检查和发布测试再交给它。这样是最安全的方式。

下面我就给你一步步介绍下如何实现集成和管理。如果你也在折腾 Hermes，欢迎关注

HermesCN 的 X 账号 @hermescn_org，或者去 HermesCN 中文社区 看中文文档和实践教程。

开始前需要准备什么

这套流程适合已经部署 Hermes、能够通过 SSH 登录服务器的人，当然如果是在本机上配置，就更加省事一些。如果你还没有安装 Hermes，可以先看

Hermes 官方文档。

需要准备：

  • 你有权管理的 X 账号，以及可创建应用的 X 开发者账户。
  • 运行 Hermes 的服务器和对应 SSH 登录权限。或者是在本机配置，不需要使用 SSH 和 script。
  • 安全保存密钥的位置，例如密码管理器。
  • 服务器上的 X 操作工具。本次实操使用 xurl，由 Hermes 准备适配该环境的一次性配置脚本。

建议给目标 X 账号使用独立浏览器 profile，尤其是同时管理多个 X 账号时，授权前要看清页面上的用户名，不要操作错账号。

下文所说的 X profile，是 X 工具里的应用或账号配置，不是必须新建一个独立的 Hermes Agent profile。多账号可以复用一个应用，也可以使用不同应用；无论采用哪种方式，都要明确应用、授权用户和实际操作账号的对应关系。

1. 在 X Developer Console 检查额度、创建应用

打开

X Developer Console

，进入 Credits 页面检查余额和消费上限。

建议低频使用的账号先充值 5 美元，用得多一些的可以先充 10 或 20 美元。实际充值选项、接口价格和消耗，以控制台及

X API 计费文档

为准。

然后进入 Apps，点击 Create App，填写一个容易辨认的应用名，Project Access 选 Production 就可以了。

创建成功后，控制台可能展示 Consumer Key、Secret Key、Bearer Token 等。对于提示只展示一次的密钥，立即保存到密码管理器。下面使用 OAuth 2.0，配置时要用的是对应的 Client ID 和 Client Secret，不要混用。

2. 启用 OAuth 2.0，设置回调地址

进入应用的 Keys & Tokens，在 OAuth 2.0 Keys / User authentication settings 下点击 Set up。界面名称可能调整，以你看到的控制台为准。

本次演示的 App permissions 选择了 Read and write and Direct message，包含读写和私信相关权限；如果只准备发帖、转发，选择 Read and write 即可。Type of App 选择 Web App, Automated App or Bot。具体能否读取或发送私信，还要看 OAuth 授权时申请的权限，后面的使用场景会说。

本次配置脚本使用的 Callback / Redirect URI 是下面这个地址。让 Hermes 准备脚本时，也要求它使用同一个地址：

http://localhost:8080/callback

Website URL 填写与你的应用相关的有效网址。回调地址则要与脚本完全一致，包括协议、端口和路径。

保存后，从 OAuth 2.0 的凭据页面取得 Client ID 和 Client Secret，同样找个安全的地方保存下来，后续会用到。

3. 让 Hermes 准备脚本，但不要把密钥交给聊天窗口（仅限 SSH 服务器用户）

如果你用 SSH 服务器远程部署，或者公用服务。使用 SSH 登录来填写私钥，不要通过 Hermes Agent 直接配置，这样是比较安全的。如果你是本机使用 Hermes Agent，可以直接让它创建存放 secrets 的位置，然后人工保存即可。

可以把下面这段交给 Hermes，并替换账号名：

我要为 X 账号

@xxx

添加自动化集成， X 应用配置名使用 xxx。 请先检查服务器现有 X 工具及版本，并准备交互式配置脚本。 如果已有其他账号配置，只参考其结构，不读取或回显其密钥， 不要修改已有账号，不要切换默认应用或默认用户。 脚本由我在私密 SSH 终端运行： - 交互输入 Client ID 和 Client Secret，Secret 输入不回显； - 不把 Secret、token 或完整 OAuth 回调 URL 写进日志； - 明确凭据保存位置和文件权限； - 使用受支持的 OAuth 2.0 PKCE 流程，保留 state 校验； - 使用 http://localhost:8080/callback 作为回调地址； - 检查是否支持在 SSH 终端手动粘贴回调 URL；如果不支持，先说明可用方式，不要生成无法完成授权的脚本； - 授权后只检查身份，不发帖、不转发、不处理私信、不建定时任务。 完成后返回脚本路径、执行方式和不含密钥的说明。

已有配置可以作为参考，但不是前提。如果这是第一个账号，直接告诉 Hermes 从零准备，先核实本机工具支持的认证流程。

Hermes 会返回脚本路径，例如下面这个。它不是内置命令，执行时以 Hermes 实际生成的路径为准：

/root/setup-x-profile.sh

4. 在私密 SSH 终端完成授权

在自己的电脑上登录服务器：

ssh <你的服务器用户>@<你的服务器地址>

运行上一步得到的脚本：

bash /root/setup-x-profile.sh

脚本依次提示输入：

X Client ID: X Client Secret:

随后脚本会生成 X 授权链接。用已经登录目标账号的浏览器打开，确认页面显示的是你要授权的账号，再点击 Authorize app。

授权后，浏览器会跳转到类似下面的地址：

http://localhost:8080/callback?state=<本次状态值>&code=<本次授权码>

如果脚本已确认支持手动粘贴回调 URL，浏览器里的 localhost 页面打不开时，可以复制地址栏里的完整 URL，粘贴回仍在等待的同一个 SSH 终端。脚本会校验 state 并交换 token。

5. 让 Hermes 检查账号，再试一次发布

授权完成后，不用自己再敲检查命令，回到与 Hermes 的聊天，直接告诉它：

授权已经完成。 请检查这个配置，读取当前登录账号，确认用户名是否正确。 只做读取检查，不发帖、不转发、不读取私信，也不要输出凭据。

它返回的账号没问题，就可以试发一条内容。先把账号和文案说清楚：

我要用 @账号A 发布下面这段内容： <完整文案> 先检查排版、链接和当前账号，给我看最终预览，暂不发布。

确认后，再告诉它“用 @账号A 发布刚才确认的版本，完成后返回帖子链接，并重新读取核对作者和正文”。需要另一个账号转发，就接着指定 @账号B 和这条帖子的链接。

引用帖也一样，提供原帖链接和自己的评论，让 Hermes 先预览。如果接口不支持，让它说明原因，不要擅自改成另一种发布方式。

6. 配好以后可以怎么用

简单分享一些常见用例和技巧，更多更复杂的可以在社群里面交流。

在聊天里改稿、排版，然后发布

最简单的用法就是把一段想法、活动信息或者文章草稿发给 Hermes，跟它聊一聊怎么表达。比如：

把下面这段活动介绍整理成适合 X 的文案，保留时间、报名链接和参与条件。 语气自然一点，不要加我没说过的评价。先给我看，不要直接发布，等我确认后发布。

不满意就继续改，确定后再让它发布。这样从整理内容到发出去都能在同一个对话里完成。多账号运营时，每次都带上账号名；同一份内容要发到不同账号，也先分别看一遍文案。

读取私信，整理需要回复的内容

如果你需要处理合作咨询、活动报名等私信，可以让 Hermes 读取近期消息，整理哪些需要你回复，再帮你起草。读取和发送私信都需要相应的 OAuth 权限，还记得刚开始的那个选项吗？

可以先从一次读取开始：

检查是否已有读取私信的授权；如果没有，先告诉我需要补什么。 有权限的话，读取近期私信，整理需要我回复的消息，并起草回复。 结果只发到当前私密对话，不向任何人发送私信。

测试可用后，再约定检查频率和提醒位置，配置定时检查。需要发私信时，明确收件人和最终正文再执行。这里只是定期读取新消息，不是开了权限就自动开始实时监听。

搜索内容、关注关键词和账号动态

还可以让 Hermes 找某个话题最近的讨论、收集内容选题，或者定期检查你关心的账号有没有新动态。

这类需要频繁读取的任务，我不建议一开始就用 X 官方 API 批量跑，成本需要单独算。可以考虑第三方 API，这篇先不展开。想了解的可以去我的 Telegram Channel 查看技巧。

Hermes 还有单独的 x_search 工具，走的是 xAI/Grok 搜索，和前面用来发帖、读私信的 xurl 不是一回事。已有 SuperGrok 或 X Premium+ 订阅的用户，可以尝试通过 OAuth 接入，使用订阅额度，而不是另外购买 X Developer Credits。详情可以参考官方文档

https://hermes-agent.nousresearch.com/docs/user-guide/features/x-search

建议添加费用计算和提醒

由于官方的 X API 挺贵的，所以我建议你可以告诉 Hermes Agent，就是在任何涉及到 X API 调用的场景都计算一下实际调用的开支，包括 Credits 或者是以美元计费的花费。这样的话你可以知道是不是有一些操作非常的费钱，可以优化。还有就是是不是又要充值了？

HermesCN 是面向中文用户的 Hermes Agent 社区，有中文文档、安装教程、Skills 和实践案例。想继续交流用 Hermes 管理社交媒体、整理内容和发布的做法，欢迎通过
