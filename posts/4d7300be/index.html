如何自动化获客

更新于2026-09-16|toolssoftware
|总字数:5.6k|阅读时长:16分钟|浏览量:

（说明：文中的冷启动短信/邮件触达与平台数据抓取，在部分地区法规和平台规则下有限制，落地前请自行确认。）

读完这份指南，你会知道怎么为任何东西自动生成线索——无论你卖的是线上数字产品，是给自家生意找客户，还是一个产品都没有、只想生成线索再转卖给企业。

方法其实只有一个：找到已经在付钱的人，把他们的数据抓下来，做出能触达他们的东西，然后放到他们看得见的地方。唯一会变的是最后拿到线索的人是谁。

读完你会拥有：

一个清楚知道谁会买你产品的 agent

一份用他们自己三个月原话写成的买家画像

从这份画像生成的广告素材，每个角度好几版

一个把线索送进你产品的 whop ads 广告活动

一个能找出「这个行业要修的那个东西」的扫描器

一条本地企业愿意按月付费的线索管道

全部按计划自动跑，只有少数几件事留给人手动

用哪个 agent？grok bot 还是 hermes

两个都能跑完这篇文章里的所有东西，系统也完全一样，区别只是你愿意做多少配置。

grok bot 上手简单。它自带一台电脑，有终端、浏览器和文件系统，你像聊天一样跟它说话。所以做法是：先用 claude 把整套系统写成一个 skill 文件，然后把这个文件连同 API key 和它需要的工具权限一起交给 grok bot。它读了 skill 就开始跑。你也可以用 chatgpt 或 grok bot 自己来写这个 skill，但我自己是用 claude 写的。

也就是说，普通人也能跑：你什么都不用配置，只要给 grok bot 一个文件和几个 key，它就开始干活。

hermes 起步更技术化，跑起来之后反而更省心。它按计划运行——grok bot 也能做计划任务，但 hermes 就是为这个建的。配置 hermes 只需要给 claude 一段 prompt：你给它 hermes 的文档和一个来自

@BotFather

的 telegram bot token，它就会把 hermes 作为常驻服务部署到 railway 上。然后你把同一个 skill 文件、同一批 API key、同样的工具权限交给 hermes，之后 prompt 都通过 telegram 发给它。

所以 skill 文件才是核心。用 claude 写出来，两个 agent 都能跑。这篇文章里的每一段 prompt，最后都是这个 skill 文件的内容。

下面我说「agent」，指的都是这两个里的任意一个。

skill 文件

skill 文件本质上就是一份文档，告诉 agent 怎么干一件活：步骤是什么、按什么顺序、用哪些工具、要记录什么。你写一次，任何读到它的 agent 都能跑这个活。

你用 claude 来写（用 codex 也行）。把文章里的 prompt 粘进一个新对话，告诉 claude 你要跑哪条 pipeline，让它把这些 prompt 变成一个完整的 skill 文件——规则在最上面，步骤在下面。它会回给你一个 .md 文件，你保存下来，交给 grok bot 或 hermes。

​ 把这些变成一个用于 [pipeline 一/二/三] 的 skill 文件。

​ - 这是我的 prompt：[粘贴进来]

​ - 把运行规则放在最上面：一个行业或一个细分一张表，绝不跨表读；任何会接触真人或花钱的动作，先停下来问我；不确定的东西标成 review，不要猜

​ - 然后按顺序列步骤，每一步说明它用什么工具、读什么、写什么、把什么交给下一步

​ - 列出这个 agent 跑起来需要的所有 API key 和工具权限，让我一次性给全

​ - 写得让一个从没看过这篇文章的 agent，只看文件就能跑起来

​ - 告诉我这里面你觉得哪些地方说得不够清楚、会让 agent 去猜

哪一半是你的

这篇文章是给三种人写的，各人跑的部分不一样。

如果你在卖数字产品，或者想做，就跑 pipeline 一。线索是你的，广告是你的，买家落在你的页面上。

如果你自己有个生意，就跑 pipeline 二给自己用：找出需要你这门生意的人，把修复效果做到他们自己的物业上，把修复展示在业主面前，线索就来了。如果你是生意主人，跳过 pipeline 三。

如果你既没有产品也没有生意，就把 pipeline 二接上 pipeline 三：为某个城市的某个行业生成线索，卖给做这个活的企业。

pipeline 一：数字线索

这一条是给有产品（或者有产品想法）的人用的。你要弄清楚到底是谁买它、他们在哪，把他们过去三个月说过的话全抓下来，然后用这些做广告。（你不需要担心自己以前从没投过广告，现在用 whop ads 投起来很容易。）

从产品开始

agent 得先理解产品，才能找到买家。它做什么、卖多少钱、解决什么问题，以及一个人得相信自己是什么样的人，才会想要它。

所以第一段 prompt 是产品，回来的是买家：他们的人口学身份，以及他们的心理画像。比如「34 岁、住在德州的男性」是人口学；「试过好几种办法、为没一个成功而沮丧的 34 岁男性」是心理画像。

​ 这是我的产品：[描述它，或者把页面粘进来]。

​ - 告诉我谁会买这个。年龄、处境、在做什么、处在人生哪个阶段

​ - 告诉我他们在这些表面之下是什么样的人。他们试过什么、害怕什么、绝不肯承认自己想要什么、用什么说法解释自己为什么还没做成

​ - 告诉我这些人在网上的什么地方。具体的 subreddit、facebook 群组、youtube 频道、tiktok 账号、discord、论坛。要实际的名字，不要品类

​ - 对每一个地方，告诉我他们为什么在那儿、在那儿聊什么

​ - 告诉我哪些地方有买家，哪些地方只是些嘴上聊的人

​ - 如果你不确定一个地方是不是真实存在、是否活跃，就直说，不要列进来

抓三个月的数据

然后 agent 去那些地方，把这三个月的东西全抓下来：帖子、评论、回复、人们问的问题、他们抱怨的事、他们用的词。apify 对这些平台每一个都有 scraper，agent 通过 apify mcp 来跑。

三个月足够看出什么在重复，又不会旧到失效。

​ 从你列出的每一个「有买家」的地方，抓最近三个月的数据。

​ - 用 apify mcp。reddit、facebook 群组、youtube 评论、tiktok 评论，每个地方选合适的 scraper

​ - 抓帖子和高赞评论、回复。保留每一条的来源 url、日期和互动量

​ - 把出现超过三次的每一个问题写下来，用他们自己的原话，附上出现次数

​ - 把他们对「自己试过的东西」的每一个抱怨写下来，用他们自己的原话，附上出现次数

​ - 把描述问题时用的说法，和描述他们其实想要什么时用的说法，都写下来

​ - 告诉我他们已经为什么付过钱，以及他们对那东西的评价

​ - 把这些写成一份画像，引语和计数都在里面，按次数排序

​ - 凡是你在猜而不是在引用，都标出来

agent 的活是找出重复最多的是什么。

创意计划

在动手做广告之前，画像要先变成一个计划。agent 读画像里的内容，定出 angles——也就是出现次数最高的抱怨或欲望；再定出每个 angle 下面的 hooks——也就是画像里说出这件事的原话。

然后它算清楚 whop ads 需要什么。whop ads 跑在 meta、facebook 和 instagram 上，所以素材是竖版视频和静图，用 meta 的三种尺寸比例。agent 读 whop 的文档就知道这些，而计划会写明每个素材用在哪里。

​ 从画像生成创意计划。

​ - 取出现次数最高的三个抱怨或欲望，把每一个做成一个 angle

​ - 每个 angle 写三个 hook，都要用画像里的原话，不要用我的措辞

​ - 每个 hook 说明视频里显示什么、静图里显示什么。要显示他们描述的想要的结果，不是产品

​ - 读 whop 的广告文档，告诉我通过 whop ads 投 meta 需要哪些格式和尺寸

​ - 每个素材说明它投在哪个位置：信息流、stories、reels

​ - 每个素材结尾都是同一个 offer 和同一个结账链接

​ - 如果某个 angle 在画像里素材不够、写不出三个 hook，就砍掉并说明原因，不要硬凑

三个 angle、九个素材。够用来学到东西，又不会多到把预算摊成零。agent 通过 replicate 或 fal 来生成，看你给了它哪个的 key。目前 gpt image 2.5 是最好的图像模型，seedance 2.5 是最好的视频模型，所以它会调这两个，两个都能直接从计划里出来，不用再额外给 prompt。

开跑 whop ads

whop ads 跑在 whop 自己的 meta 代理账号上。你是从 whop 后台启动，不是在 meta 的原生广告管理器里，广告通过处在 meta 最高层级的账号跑在 facebook 和 instagram 上。这意味着竞价里优先、规模化后千次展示成本更低，被拒的次数也远少于一个新账号。这真的很爽。

pixel 已经在你的 whop 页面上，而且它用真实支付数据来做归因。所以当一次转化被计入时，是真的有人付了钱。whop 还会把转化回传给 meta 的优化系统，于是 meta 用同一套数字来学习。

agent 按计划把这一切建起来：一个 campaign，三个 ad set（一个 angle 一个），每个 ad set 三个素材。每个 ad set 从 [占位] 一天开始。要盯的数字是「每单成本」对「你产品的价格」。如果某个 ad set 的每单成本连续三天高于产品价格，就暂停它。agent 每天从广告后台拉花费、从 whop 拉净收入，并排放在一起——这是唯一能真正看清它的办法。

投放资金当天可以从你 whop 的待结算余额里出。广告带来买家，买家养广告。

agent 的每日报告是每个 ad set 四个数字：花费、点击、成交、每单成本，以及哪个 angle 在赢、有什么该暂停。

用 whop ads 本身不用付钱，你只付投放花费，仅此而已。

收集线索

广告把人送到你的页面，产品就是你第一段 prompt 里给它的那个。页面上说的话和广告一样，用的还是他们的语气。

对点了但没买的人，agent 会去跟进。whop 会告诉你谁访问过、谁到了结账这一步。

这就是 pipeline 一：产品、买家、三个月的原话、计划、素材、广告。线索始终是你的。

pipeline 二：实体线索

这一条是线索给本地企业用的。你从公开数据里找到一处有可见问题的物业或商铺，把修复效果渲染到那处真实的物业上，把这张渲染图送到业主眼前，回应你的人就是线索。

选行业

选一个词就能说清楚的行业：太阳能、屋顶、园林、泳池、遮阳篷、围栏、车道、招牌。买家必须在消息到达之前就已经想要这东西——所以这个行业得是那种「物业或商铺本身就告诉你他们需要」的。你不是在创造需求，你是在发现需求。

其中一些业主是家庭，一些是企业，方法不管这些。带泳池的房子是家庭。没有招牌的咖啡馆是企业。屋顶空空平平的仓库是企业。屋顶旧了的房子是家庭。要紧的是：这个行业要修的那个东西，能从公开数据里看出来，agent 才能找到它。

所以第一段 prompt 是行业，回来的是数据在哪。

​ 我在为 [城市] 的 [行业] 生成线索。

​ - 告诉我这个行业需要做的时候，物业或商铺看起来是什么样。什么东西可见、从哪里看得见

​ - 告诉我哪个公开数据源能显示出它。卫星影像、街景、挂牌照片、商户信息、许可记录、房产记录。要具体到数据源，以及它会返回什么

​ - 告诉我要找的买家是家庭还是企业，各自我能拿到什么联系数据。只有地址，还是也有邮箱和电话

​ - 告诉我该用哪一个判定条件。只要一个，不要一串

​ - 告诉我渲染图需要显示什么，渲染进哪张图里

​ - 如果这个行业在公开数据里没有可见信号，就直说，不要编一个出来

找出候选

判定条件只有一个：有那个行业要修的东西。你叠加的每一个过滤条件都会砍短名单、加进一个猜测，而猜测会互相放大。第一批发出去之后，行业自己会告诉你哪些过滤值得做，这是很有价值的信息。

数据是公开的，而且大多免费。数据源取决于行业，这也是上一段 prompt 存在的原因。agent 只用上一段 prompt 指出的那一个数据源去读。给判定条件再加第二个数据源，就是名单缩水的开始。

多数影像 API 都有一个免费的元数据检查，能告诉你影像是否存在、有多旧，然后你才需要为图像付费。agent 对每个地址先跑这个，只对返回「较新」的付费。

​ 为 [城市] 的 [行业] 建候选名单。

​ - 从房产记录或商户信息里（看这个行业需要哪个）拉出 [区域] 里的每一个地址，能公开拿到的业主名字也一起拿

​ - 对每一个地址，先检查影像或挂牌照片是否存在，再决定要不要拉东西；什么都没有、或者影像超过三年的直接丢掉

​ - 通过这一关的，拉我们选定的那一个数据源，检查那一个判定条件

​ - 通过判定的，拉渲染需要的参考图

​ - 写一张表：地址、业主、联系数据、来源 url，以及一个标记——判定是明确还是边界

​ - 边界情况标成 review，不要判成进或出

​ - 做完了告诉我这批花了多少 API 调用

渲染修复效果

图像模型把修复效果做到他们真实的物业上。

它必须是编辑。模型拿到参考图，只改这个行业要修的那一个东西。

这里需要好几帧参考图，原因和我那篇圣诞灯文章里一样：只有一张图，模型对图外的一切只能靠猜。三到四张参考图，它才够用。

触达业主

三个渠道可以做这件事：邮件、短信、明信片。三个渠道用的渲染图一样，指向的地方也一样——一个专为这处物业建的页面，最上面是渲染图，下面是一个表单，问他们希望什么时候报价。

用哪个渠道取决于你手里有什么。对企业，你通常能从商户信息里拿到邮箱和电话，所以邮件和短信都行，agent 用你给它的发送通道来发。对家庭，你通常只有地址，那就只能寄信。在我自己的测试里，明信片的效果本来就远远好于邮件和短信。寄信这块有多家明信片公司提供 API，你可以把权限给 agent。你批准之后，agent 会自己把这一批发出去。

​ 为 [城市]、[行业] 准备外联批次。

​ - 对表里每一处物业，按我们手里的数据选渠道。只有地址就寄信。有邮箱或电话就加上邮件或短信

​ - 渲染图和每一条消息一起发。寄信就整版放在正面，邮件就放在正文里，短信就放页面的链接

​ - 配一句话，用大白话说清楚：这是你家/你店，修好的样子是这样的，想看要做些什么就点这里

​ - 每处物业建一个页面，最上面是渲染图，写上地址，再放一个表单问他们希望什么时候报价。所有渠道都指向它

​ - 明信片上的二维码位置在版面上留空，真实的码我自己合成上去

​ - 每个地址、邮箱、号码在进批次之前都要验证

​ - 准备好这一批就停。给我看每个渠道的数量，以及各一个样例

业主打开页面，看到自家的地方，填上时间，这次表单提交就打了时间戳、绑定了他们的地址。

接住回应

扫码、填表、回复，这些就是线索。它带着地址、业主名字、他们想要的报价时间，还有一张这处物业的渲染图。线索一落地，agent 就记进表里，而这张表就是下一条 pipeline 里你要卖的东西。

打开了、扫了码但没填表，也值得记下来。一个人看了自己家修好的样子、只是还没要报价，他是有热度的，第二批会去跟进这些人。

如果你就是生意主人、给自己跑这条线，到这里就结束了：agent 做完了寻找、渲染和发送，剩下的只有对话，而对话由你来。

这就是 pipeline 二：行业、发现、渲染、触达、接住。

pipeline 三：把线索卖出去

现在线索要交给做这个活的企业，你为它收钱。

找到这些企业

google places、行业、城市。过滤出老板亲自经营的公司而不是加盟店——因为看邮件的正是老板；评论数在 15 到 200 之间；有真实地址等等。

agent 拉出名单，对每一家记下它覆盖的区域。

触达企业

你其实不用去推销。给企业的消息里带着一批已经生成好的、就在他们区域里的线索样本。老板看到的是完成度很高的线索，他脑子里的问题会变成「这样的还有多少」，而不是「这玩意行不行」。有地址就寄信，有邮箱就发邮件，都有就都做。

​ 为 [城市] 的 [行业] 公司准备外联。

​ - 从 google places 拉出 [城市] 里所有评论数在 15 到 200 之间、没有加盟店特征的 [行业] 公司，并记下每家覆盖的区域

​ - 对每一家，从表里挑还没有卖出去、离他们最近的三个线索

​ - 用这三个做一页 pdf：街道和区域、渲染图、以及填表时他们要求的时间

​ - 消息用大白话写：这是你附近这周要 [行业] 报价的三个人，就是他们

​ - 链接或二维码指向这份 pdf

​ - 再起草一封一周后发的跟进邮件，带同样的三个线索

​ - 全部准备好就停。第一封信由我发给任何回复的老板

​ - 如果一家公司在它覆盖的区域里凑不够三个线索，就跳过并说明，不要把跨城的线索发过去

定价

两种方式：按条收费，或者按月托管整条 pipeline。

按条收费用在第一个月。企业为自己拿到的线索付钱，看着线索成交，也就知道了对他们来说一条值多少。这个数字对照的是这个行业的平均客单价。

按月托管用在第二个月。企业已经看到线索成交了，更愿意为一个固定数字买下整条管道：在一组 zip code 里独家，每月 [占位]，agent 让这条管道只为他们一家在那些 zip 里继续跑。

交付

线索落在一个企业能看到的看板上：地址、业主、渲染图、表单填写、时间戳、状态。

让他们持续付钱的东西是：看板在他们什么都不用做的情况下自己满起来，以及从里面成交的第一单。

agent 跑什么

三条 pipeline 加起来，agent 负责：寻找、读取、画像、素材、物业扫描、渲染、建页面、外联批次、表格，以及每日报告。几乎全包了。

有三件事留给你。

渲染图在批次发出之前要你检查；和商家老板的第一次对话；任何广告的预算。agent 提建议，你拍板。

什么会崩

公开影像在有些地方是旧的。agent 读到的那张图可能是三年前的，而它看到的问题早就被修好了。元数据检查在有些数据源上会告诉你日期，有些不会，所以任何新区域的第一批就是你发现它有多旧的地方。信之前先看几张。

whop ads 会拒收带承诺的素材。不能编收入数字，不能用假证言，不能有任何暗示买家会得到某种结果的表述。合规检查在投之前跑，一条被拒的广告会拖累整个广告组。记住这一点。

企业老板通常不会回第一条消息。他们会回第二条，或者回一周后的跟进。建议至少跟进两次。

从哪里开始

挑一条 pipeline。有产品就跑 pipeline 一。没有就把 pipeline 二接 pipeline 三。

第一批发出之前，每一张渲染图都看一眼。那些做错的图会告诉你该往渲染 prompt 里加什么。

然后带着学到的东西，做同城的第二批。

祝你配置愉快。
