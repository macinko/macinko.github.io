NOFX 详细部署教程

1. 项目简介

NOFX 是一个开源的、AI 驱动的自主交易操作系统，其核心定位是下一代 AI 交易操作系统。它将大语言模型（LLM）与多个加密货币交易所连接，让 AI 自主做出交易决策，无需人工干预。

核心特性：

  • 多 AI 支持：集成 DeepSeek、Qwen、GPT、Claude、Gemini、Grok、Kimi 等多种 AI 模型，可随时切换
  • 多交易所支持：支持币安（Binance）、Bybit、OKX、Bitget、KuCoin、Gate、Hyperliquid、Aster 等交易所
  • 策略工作室：提供可视化策略构建器，可配置币种来源、技术指标、风险控制等
  • AI 竞赛：多个 AI 模型可在同一市场实时竞争，排行榜按表现排名
  • 实时仪表盘：显示实时持仓、盈亏、AI 决策日志（含思维链推理）
  • x402 微支付：无需 API Key，只需 USDC 钱包即可按请求付费使用 AI 模型

重要提示：NOFX 目前主要支持加密货币市场（期货），股票、外汇、商品等市场正在开发中。AI 交易是实验性的，不保证盈利，建议始终使用小额资金进行测试。

2. 部署前准备

2.1 硬件要求

根据官方 FAQ，最低配置要求如下：

  • 操作系统：Linux、macOS 或 Windows
  • 内存：最低 2GB，推荐 4GB
  • 硬盘空间：应用和日志需要约 1GB
  • 网络：稳定的互联网连接

2.2 软件要求

使用 Docker 方式部署（推荐）：

  • Docker 20.10+
  • Docker Compose V2

使用源码方式部署：

  • Go 1.21+
  • Node.js 18+
  • TA-Lib 库（技术指标计算依赖）

变量名 类型 默认值 必填 说明

NOFX 支持多种 AI 模型接入方式。

7.1 使用 API Key 模式

  • OpenAI（GPT 系列）

  • BlockRun（Base 链）

8. 配置交易所

8.1 获取 API Key

币安（Binance）：

  1. 登录币安账户 → API 管理
  2. 创建 API → 启用合约交易权限
  3. 建议使用子账户以隔离风险

Hyperliquid：

  1. 访问 Hyperliquid App → API 设置

8.2 重要设置：币安持仓模式

必须将币安切换为双向持仓模式，否则会出现错误（code=-4061）：

  1. 登录币安合约
  2. 点击右上角 ⚙️ 偏好设置
  3. 选择 持仓模式 → 双向持仓
  4. 注意：切换前需先平掉所有持仓

9. 创建交易员并开始交易

9.1 创建交易员

在 Web 界面中完成以下步骤：

  1. 配置 AI 模型：添加 API Key 或配置 x402 钱包
  2. 连接交易所：添加币安/Hyperliquid 的 API 凭证
  3. 创建交易员：将 AI 模型与交易所组合
  4. 开始交易：在仪表盘监控表现

9.2 监控交易

仪表盘提供以下功能：

  • 实时持仓：显示当前所有仓位
  • 盈亏统计：权益曲线、胜率、盈亏比
  • AI 决策日志：每个决策的完整思维链（Chain of Thought）
  • AI 竞赛：多 AI 模型的实时 ROI 对比排行榜

9.3 风险控制

NOFX 内置了多层风险控制机制：

  • 仓位限制：每个资产有仓位上限（山寨币 ≤1.5x 权益，BTC/ETH ≤10x 权益）
  • 杠杆控制：动态杠杆 1x-50x，根据资产类型调整
  • 保证金管理：总使用率 ≤90%
  • 止损止盈：强制要求止损止盈比 ≥1:2
  • 防重复开仓：防止同一资产/方向重复持仓

问题：DATA_ENCRYPTION_KEY not set 错误

解决方案：确保 .env 文件中已设置 DATA_ENCRYPTION_KEY。如果自动生成失败，可以手动生成一个 base64 编码的 32 字节密钥。

10.5 交易员不开仓

常见原因：

  • AI 根据市场情况决定“等待”
  • 余额或保证金不足
  • 达到持仓上限（默认最多 3 个仓位）

11. 安全建议

根据官方文档，部署时请务必注意以下安全事项：

  1. API Key 安全：
    • 永远不要将 API Key 提交到 git
    • 使用环境变量存储敏感信息
    • 限制 API Key 的 IP 访问
    • 在交易所启用 2FA
  2. 交易前测试：
    • 先在测试网测试策略
    • 从小额资金开始
    • 充分理解风险
  3. 生产环境建议：
    • 使用 HTTPS（可通过 Cloudflare 配置）
    • 设置 TRANSPORT_ENCRYPTION=true 启用传输加密
    • 启用管理员模式限制访问

12. 部署架构总结

部署方式 适用场景 优势 命令
一键脚本 快速体验 最简单 `curl … install.sh
Docker Compose 生产环境 灵活可控 docker compose up -d
源码构建 定制开发 完全可控 go build && ./nofx

部署完成后，访问 http://127.0.0.1:3000 即可开始使用 NOFX。如需云端部署，可参考 Railway 部署方案，或通过 Cloudflare 配置 HTTPS 访问。
