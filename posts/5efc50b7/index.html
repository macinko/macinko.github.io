想在闲鱼卖服务，照着这篇做：从 0 到 1 上架自己的服务

更新于2026-09-13|toolssoftware
|总字数:5.9k|阅读时长:17分钟|浏览量:

我用 29.99 元的 OpenClaw 远程部署服务跑通了第一次成交。打开闲鱼，跟着这 12 步，把自己的技能或点子变成一项可以出售的服务。

先打开闲鱼，边看边做

这篇文章的使用方式很简单：

  1. 手机打开闲鱼；
  2. 准备一项自己能完成的技能或服务；
  3. 从第一步开始操作；
  4. 每完成一步，就把对应内容填进自己的商品页；
  5. 一个小时内发布第一版，接下来用真实咨询验证需求。

跟着文章做完，你应该得到五个结果：

  • 一句说得清楚的服务定位；
  • 十个同类商品组成的对标表；
  • 一份边界明确的商品描述；
  • 一到四个真实可购买的价格规格；
  • 一项已经发布、可以接受咨询的闲鱼服务。

发布只是起点。最终目标是完成第一笔真实交易，确认确实有人愿意为这个问题付钱。

你哪天突然想做闲鱼服务，可以回来搜这篇：Lany 小生的闲鱼服务上架手册。

这是我今年折腾的第一个副业

大家好，我是 Lany 小生。

白天在一线做全栈开发和技术 Leader，晚上独立开发，也会折腾一些副业项目。

今年年初，OpenClaw 开始被越来越多人讨论。我自己把它跑起来以后，发现身边有不少人感兴趣，但很多人会卡在安装、环境、模型接入和渠道配置上。

对开发者来说，看文档、装依赖、处理报错是正常工作。对只想把工具用起来的人来说，这些步骤就是一道门槛。

我当时冒出一个很简单的想法：

既然有人想用，又不想自己折腾，我能不能直接卖部署服务？

我没有先开发一键安装器，也没有做网站。当天就在闲鱼上架了一个商品：

OpenClaw 本地远程部署服务

商品定价 29.99 元，页面后来显示有 41 人“想要”，累计赚了大约 500 元。

这笔钱不多，但它是一次完整的需求验证。我把自己会做的一件事，整理成服务，放到有人搜索的平台上，最后真的有人付钱。

这篇文章就讲这段经历。如果你也有一个技能或点子，想先看看有没有人愿意买，可以照着下面的步骤做一遍。

第一步：先找一个你能立刻解决的小问题

第一次上架服务，别从“我会什么”开始写。

“我会写代码”“我会用 AI”“我会部署服务器”都太宽。买家不会为你的技能列表付钱，他只关心自己的问题能不能被解决。

OpenClaw 这个案例里，问题很具体：

  • 用户已经知道 OpenClaw；
  • 用户确实想使用；
  • 用户卡在安装或配置；
  • 我可以通过远程协助解决；
  • 安装是否成功可以当场检查。

我把它整理成了一句话：

我帮想使用 OpenClaw、但卡在安装配置的人，通过远程协助把程序跑起来。

你也可以套用这个句式：

我帮【哪类人】，解决【哪个具体问题】，通过【什么交付方式】，得到【什么可以检查的结果】。

例如：

  • 帮第一次搭博客的人，把 WordPress 从旧服务器迁移到新服务器；
  • 帮笔记太乱的人，把现有文档整理成一套 Obsidian 知识库；
  • 帮不会处理格式的人，把一篇 Markdown 长文排成可复制的公众号文章。

范围越具体，你越容易写清商品页，也越容易判断订单能不能做。

第二步：把技能整理成一件可以买的服务

复盘这次上架，我现在会先写清七个信息：

要写清的内容 我的 OpenClaw 服务
目标用户 想使用 OpenClaw，但卡在安装配置的人
解决的问题 环境、依赖、模型接入和基础渠道配置
交付结果 在约定设备上正常启动，并完成基础调用
交付方式 远程协助部署
预计时间 常规环境约 30–60 分钟
测试价格 29.99 元
不包含 付费 API、长期运维、二次开发和订单外需求

这七项写清楚，你的点子才从“我能做”变成“别人可以买”。

我当时用 29.99 元，是为了降低第一次成交的门槛，顺便验证自己的交付流程。这个价格并不适合所有人，也不适合长期照搬。

只看操作时间，29.99 元对应的每小时毛收入大约是 30 到 60 元。加上售前沟通、等待和售后，实际效率会更低。

所以低价适合测试，不适合成为永久价格。先用它拿到真实咨询和第一批订单，再根据交付难度重新定价。

第三步：从“发服务”入口开始上架

打开闲鱼的发布入口后，不要选择普通的“发闲置”。在“自己卖”区域找到 发服务，进入服务发布流程。

进入以后，平台会展示就业咨询、软件开发、家庭保洁、画画约稿、Office 处理制作等服务方向。我做的是 OpenClaw 部署，所以选择了 软件开发。

选类目时不要只看哪个分类收入示例更高，先确认三件事：

  1. 你的服务确实属于这个类目；
  2. 这个类目允许你填写需要的交付方式和计价方式；
  3. 你的账号满足当前类目的认证和发布要求。

类目选错，后面标题和描述写得再好，也可能匹配不到真正需要服务的人。

第四步：发布前先找十个对标

选择服务方向时，页面有“看别人发的”入口。先点进去看看同类服务，不要急着直接发布。

我找对标时会记录六项：

对标信息 要看什么
标题 用户会搜索哪些具体词
首图 同行用结果图、工具图还是文字图
最低价格 对应的是完整服务还是一个真实的入门规格
多价格规格 同行怎样拆基础版、组合版和售后服务
服务范围 哪些内容包含，哪些内容需要加价
评论与问答 买家反复追问什么、担心什么

对标不是复制别人的标题和图片。它的作用是帮你看清这个类目已经形成了什么交易语言，以及还有哪些信息没人讲清楚。

第一次可以先找十个：五个互动较多的商品，再找五个与你服务范围最接近的商品。整理出高频关键词、常见价格区间和买家问题，再写自己的商品页。

截图里带有第三方账号信息，所以本文不公开原图。实际操作时，对标只用于研究，不要搬运他人的图片、文案和案例。

第五步：套用平台模板，补齐具体服务信息

进入“软件开发”的发布页面后，先上传首图，再填写具体服务内容。平台模板会提醒你描述优势、经验、服务范围和交付内容。

页面下方还需要补充：

  • 预计工期；
  • 售后服务；
  • 额外服务；
  • 计价方式，例如按次、起步价、按小时或其他；
  • 服务区域；
  • 商品规格；
  • 价格；
  • 交付方式；
  • 是否支持不满意包退。

这些字段不能随便勾。预计工期要覆盖正常交付和可能的排错时间；“不满意包退”只有在你能够明确履约条件时再开启；留言卡会让买家提交手机号，远程技术服务通常先使用平台聊天即可，没有必要就不要额外收集联系方式。

我的 OpenClaw 服务可以这样填写：

字段 示例
预计工期 常规环境当天完成，复杂环境先评估
售后服务 处理原订单范围内的安装和启动问题
额外服务 新增渠道、复杂排错、后续维护
计价方式 基础部署按次，复杂需求重新报价
服务区域 远程服务按平台实际可选范围填写
交付方式 无需邮寄，远程完成并当场验收

服务模板负责提醒你把信息补全，最终内容仍然要写成自己的真实交付范围。

第六步：用“商品规格”设置多价格

如果一个服务有不同版本，不要把所有价格都塞进描述里。进入 商品规格，添加一个规格类型，例如“服务版本”或“接入方式”。

然后把不同服务拆成独立选项。截图中的例子是：

  • 仅飞书接入版；
  • 仅微信接入版；
  • 飞书 + 微信双渠道；
  • 一次售后调试。

多价格有四个实际作用：

  1. 降低第一次咨询门槛。 用户可以先购买范围较小的基础规格；
  2. 让差异更容易比较。 单渠道、双渠道和售后服务一眼就能看懂；
  3. 减少反复报价。 常见组合已经对应明确价格；
  4. 把新增需求单独计价。 售后调试和额外渠道不会无限塞进基础订单。

开启“支持添加图片”后，还可以给每个规格配置不同图片。基础版放对应渠道的运行结果，双渠道版放两种渠道的验收图，售后规格放售后范围说明。用户不打开长描述，也能从规格图判断区别。

多价格的最低价确实更容易吸引点击，但必须对应一项真实、可以独立购买和完成的服务。不要设置一个无法成交的超低价规格，再把所有用户引导到高价版本。商品描述、规格名称和最终交付必须一致。

第七步：分别设置价格和库存，再确认发布

规格创建完成后，进入“设置价格和库存”，为每个选项填写对应价格和库存。

截图中的示例配置是：

规格 价格 示例库存
仅飞书接入版 200 元 999
仅微信接入版 200 元 999
飞书 + 微信双渠道 250 元 999
一次售后服务调试 30 元 999

这组数字只用于说明设置方法，不代表所有服务都应该这样定价。个人提供技术服务时，我更愿意按真实交付能力设置库存。例如一周只能稳定完成五单，就不要用 999 件制造无限供应的错觉。

设置完成后点击“完成”，回到发布页，再检查一次：首图、描述、工期、售后、计价方式、每个规格的价格和库存。确认交付方式后再发布。

第八步：商品页只回答买家最关心的问题

我的商品标题非常直接：

OpenClaw 本地远程部署服务

它包含了三个信息：

  1. 用户会搜索的工具名：OpenClaw；
  2. 服务方式：本地或远程；
  3. 最终卖的东西：部署服务。

你可以用这个标题结构：

【工具或问题关键词】+【交付结果】+【服务类型】

商品首图也不用做得很复杂。让用户一眼看出你处理的是哪个工具，以及这是一项什么服务。工具界面、部署完成页面或一张简洁的服务说明都可以。

描述部分需要写清服务内容、适合人群、交付结果、预计时间、支持范围和售后边界。

下面这份模板可以直接修改：

【服务内容】 协助完成______，最终达到______结果。 【适合人群】 已经______，但目前卡在______的人。 【交付方式】 通过______完成，预计需要______。 【交付标准】 1. ______可以正常运行； 2. 完成一次______测试； 3. 告知买家后续如何自己使用。 【下单前需要提供】 操作系统、设备情况、当前报错和希望实现的结果。 【不包含】 ______、______以及订单以外的新需求。 【售后范围】 处理本次交付范围内的______问题。用户自行修改、系统重装、上游更新和新增功能需要重新评估。

商品页写得越清楚，你需要重复回答的问题越少，后面的售后争议也越少。

第九步：发布后用四层漏斗看曝光

商品上架以后，很多人最关心的是曝光。

我后来发现，只看一个曝光数字没有太大用。一次成交至少要经过四步：

曝光 → 点击 → 咨询 → 下单

每一层没数据，原因都不同。

完全没有曝光

先检查标题有没有明确关键词、类目是否正确、图片和描述是否符合平台当前规则。

用户搜索 OpenClaw 时，他需要先看到“OpenClaw”这个词。只写“AI 智能助手安装”会覆盖更大范围，但也更难匹配真正需要这项服务的人。

有曝光，没人点击

检查标题、首图和价格。用户有没有在一两秒内看懂你卖什么？首图是在展示结果，还是一张只有你自己看得懂的后台截图？

有点击，没人咨询

通常是商品页没有解决信任问题。用户不知道自己的设备能不能做、最终以什么结果算完成、失败怎么办、后面出问题还管不管。

有咨询，没人下单

不要只记“这个人没买”。把他问的问题记录下来：使用什么设备、卡在哪里、想实现什么、为什么最后没有下单。

连续出现的相同问题，可以写进商品页；每个人都完全不同的需求，说明服务还不够标准。

在“我的发布”里持续维护

商品发布后，我会回到“我的发布”观察数据和互动，再做小范围调整。

可以做四件事：

  1. 微调价格。 有点击却没有咨询时，可以测试一个新的基础价格或重新调整规格差价。一次只改一个变量，并记录修改前后的咨询变化；
  2. 使用平台当前提供的擦亮或曝光入口。 如果“我的发布”里有每日曝光、擦亮等功能，就按平台提示使用。它能增加一次被看见的机会，但不能代替商品本身的需求和转化；
  3. 及时回复真实评论。 买家的公开问题可以补充商品信息，也能帮助后来的人建立信任。把高频问题整理进详情页；
  4. 更新首图和描述。 买家反复误解同一个地方，说明页面表达有问题。先改最影响点击或咨询的一处。

评论的直接价值是补足信息和信任。它是否、以及以多大权重影响推荐，平台没有在当前公开规则里给出可复现数字，所以不要买评论、刷互动或让朋友发布虚假评价。

“微调价格”和“每日擦亮”也不是固定流量密码。平台分发会变化。第一次验证更重要的是让平台和用户都能看懂：你解决什么问题，谁应该点进来，付钱以后能拿到什么。

第十步：咨询时先判断能不能交付

技术服务最容易犯的错误，是在咨询阶段免费排错半小时。买家的问题可能已经解决了，订单还没有产生。

收到咨询后，我现在先问五个问题：

  1. 你使用什么操作系统和设备？
  2. 现在卡在哪一步，有没有明确报错？
  3. 你希望最终实现什么结果？
  4. 模型或相关平台账号是否已经准备好？
  5. 是否接受当前价格、交付范围和售后边界？

可以直接这样回复：

可以先把你的操作系统、设备情况、当前报错和想实现的结果发我。 我确认环境后，会告诉你是否能做、预计需要多久，以及当前价格包含哪些内容。 密码、验证码和 API Key 不需要发给我，涉及凭据时由你本人输入。

这一步是在筛选订单。能做、边界清楚，再进入交易；明显超出范围，就重新报价或直接说明做不了。

第十一步：开始远程以前，先定义什么叫“完成”

我当时的商品描述写了“30–60 分钟完成，装好后收费”。这个说法降低了咨询门槛，但交付标准还不够清楚。

程序启动算完成，还是模型能正常回复才算完成？基础安装是否包含飞书、钉钉或其他渠道？买家后来增加一个需求，算售后还是新订单？

这些问题要在开始远程以前说清楚。

OpenClaw 基础部署可以约定成下面几个验收点：

  • 程序可以正常启动；
  • 完成一次约定模型的基础调用；
  • 订单包含渠道配置时，完成约定渠道的连接测试；
  • 买家知道配置文件、启动命令和基础使用方法在哪里。

远程操作时，我现在会守住几个基本边界：

  • 买家自己输入密码、验证码和 API Key；
  • 不把密钥放进聊天记录、截图或公开仓库；
  • 遇到订单外需求先停止操作并确认；
  • 完成以后让买家当场测试；
  • 在平台内保留范围确认和验收记录。

交付标准越具体，双方越容易判断服务有没有完成。

第十二步：29.99 元不能包含无限售后

技术服务真正消耗时间的地方，经常发生在交付以后。

用户改了配置、重装了系统、上游版本更新、第三方接口发生变化，都可能让已经能用的程序再次报错。

售后必须提前写清三个信息：

  1. 售后持续多久；
  2. 哪些问题包含在原订单中；
  3. 哪些变化需要重新评估或下单。

可以使用这份模板：

售后期限以下单前约定为准。 售后处理本次部署范围内的安装和启动问题。系统重装、用户自行修改配置、上游版本升级、第三方接口变化以及新增功能，需要重新评估。 反馈问题时请提供发生时间、操作步骤、报错截图和相关日志，不要发送密码、验证码或完整 API Key。

如果一个问题重复出现，就把它写进 FAQ、检查脚本或安装 SOP。每完成一单，都应该让下一单更容易交付。

什么样的点子适合在闲鱼快速验证

根据这次经历，我会优先选择下面几类服务：

  • 用户的问题很具体，结果可以检查；
  • 一到两小时可以完成基础交付；
  • 前几单可以人工完成，后面能够逐步标准化；
  • 不需要提前购买大量库存；
  • 失败成本低，不涉及高额资金和高责任风险；
  • 闲鱼当前存在对应的发布类目或服务场景。

环境部署、网站迁移、格式转换、数据整理、知识库整理等技能，都可以从一个范围很小的服务开始测试。

长期定制开发、需求边界不清、需要特殊资质或可能产生较高责任的服务，不适合作为第一次快速实验。

今天就能执行的一小时上架流程

如果你现在有一个点子，可以用一个小时完成第一版商品。

前 10 分钟：找对标

进入“发服务”，选择对应方向，打开“看别人发的”。记录十个同类商品的标题、首图、价格、规格和评论问题。

第 10–20 分钟：定义服务

完成“我帮______，解决______”这句话，再写清交付结果和不包含的范围。

第 20–35 分钟：填写平台模板

上传首图，写标题和服务内容，补齐预计工期、售后、额外服务、计价方式、服务区域和交付方式。

第 35–50 分钟：设置多价格

进入商品规格，添加基础版、组合版和额外服务。需要时开启规格图片，再为每个规格设置真实价格和库存。

第 50–60 分钟：检查并发布

逐项检查类目、描述、最低价格、规格差异、库存、隐私和售后边界。确认没有客户账号、服务器地址、联系方式、密码或密钥以后再发布。

发布后先收集真实咨询，不要立刻回去开发完整产品。

上架完成检查单

发布按钮点下去以前，逐项确认：

  • 标题包含用户会搜索的具体问题或工具名
  • 首图能在两秒内说明你卖什么
  • 商品描述写清目标用户、交付结果和预计时间
  • 基础价格对应真实、可以独立完成的服务
  • 多价格规格之间有清楚的服务差异
  • 每个规格的库存符合自己的交付能力
  • 售后有期限、有范围，新增需求需要重新评估
  • 商品页没有客户账号、联系方式、地址、密码或密钥
  • 下单前要问的问题已经整理成固定回复
  • 自己能够演示并验收最终结果

十项全部勾完，再发布。

发布后的七天，每天留十分钟记录四个数字：曝光、点击或“想要”、咨询、订单。漏斗停在哪一步，就只修改那一步，不要同时重写标题、图片、价格和描述。

这 500 元给我的最大价值

OpenClaw 部署服务最后赚了大约 500 元，没有成为一门规模很大的副业。

29.99 元一次、30 到 60 分钟人工操作，也决定了它当时的收入上限。

但我完成了自己的第一次验证：有人正在遇到这个问题，有人愿意付钱，我也能把约定结果交付出来。

如果订单和咨询继续增加，下一步才是做环境检查脚本、标准安装包、复杂排错套餐和持续维护服务。没有订单以前，这些都只是开发者自己的想象。

所以，如果你现在有一个不错的点子，我的建议很简单：

先把它整理成一件可以成交的小服务，完成第一笔真实交易，再决定要写多少代码。

这就是我第一次在闲鱼卖服务的完整经历，也是这份手册的第一版。

它的完成标准只有一个：你真的发布了一项服务，并开始用真实咨询修正自己的点子。

哪天你又想到一个新服务，不需要重新研究一套方法。回来打开这篇文章，从找问题、找对标、填模板、多价格和库存一路做下去。

能不能卖出，最终取决于需求、表达、信任和交付。这份手册负责让你尽快进入真实交易，而不是把时间花在发布以前的想象里。
