Grok Bot 从 0 开始，月入 5000 美金

更新于2026-09-13|aiagent
|总字数:9k|阅读时长:27分钟|浏览量:

大家好，Grok Bot作为最强个人助手，咱们不能只会用，一定要用它来创造收入。今天咱们就从 0 开始，从软安装开始，给你一步一步的详细拆解。收藏好，认真研读！

安装Grok Bot，到把服务卖给海外客户

我第一次看到 Grok Bot 的介绍时，脑子里冒出的念头很简单：这不就是 Grok 换了个壳吗？

名字里有 Grok，界面里也有聊天框。打开以后，我还是得打字，它还是会回话。只看这些，确实很容易把它当成另一个聊天机器人。

可如果只是聊天，为什么它还要准备一台云端电脑？为什么登录时会跳出 Cursor？为什么一个账号能建许多个 Bot，每个 Bot 还要填名字、岗位和工作说明？

我顺着这些问题往下看，才发现自己一开始就认错了东西。

普通 AI 的基本动作是“回答”。我问它怎么整理周报，它给我一套方法；我让它写邮件，它交给我一段文字；我问下一步该点哪里，它告诉我操作路径。真正点击网页、下载文件、登录后台、核对表格的人还是我。

Grok Bot 的基本动作是“接手”。我把任务、资料、边界和交付格式说清楚，它可以打开网页、处理文件、使用终端，在我允许的应用里继续工作。遇到登录、验证码、付款、发送或删除之类的关口，它再停下来找我。

区别就在这里。

我把普通 Grok 当顾问，把 Grok Bot 当成坐在另一台电脑前的同事。顾问告诉我怎么干，同事拿走任务，把活推进到能验收的位置。

这篇长文围绕一件具体的事往前走：我创建一个“AI 情报员”，让它每周收集 AI 行业更新，核对信息，整理成一份中文周报，但不能自行发布。我先用 299 元的小单验证交付，再把服务改成海外客户看得懂的 300、800 和 1200 美金三档。最后那张 5000 美金的账单，必须从第一个只读任务开始搭。

如果你从没接触过 Agent、Skill、Routine，这个例子已经够用。先跑通一个岗位，再谈更多花样。

先把四个容易混淆的东西分开

Grok、Grok Build、Grok Bot 名字挨得很近，做的事却不一样。

Grok 是通用 AI 助手。问答、写作、分析、图片创作，这些都属于它的主场。

Grok Build 更偏编程。它面对代码仓库、终端和开发任务，适合写代码、改项目、运行命令、排查错误。

Grok Bot 面向跨工具的完整工作。它可以去网页找资料，在文件里整理结果，再到另一个应用里继续处理。编程只是它能做的工作之一，不是它的全部。

还有一个常见误区：不要把 Grok Bot 当成一个需要自己装 Python、拉源码、配模型的开源项目。你要用的是官方提供的客户端和云端电脑。网上如果出现“本地部署版”“破解版 APK”“一键私有化 Grok Bot”，先别兴奋。产品名相同，不代表它们是同一件东西。

我判断一项任务该交给谁时，用的是一个很土但好用的办法。

如果我只想得到答案，我找 Grok。

如果工作核心是代码仓库，我优先考虑 Grok Build。

如果任务要跨网页、文件和应用跑好几步，我才找 Grok Bot。

这条判断能挡住很多无效折腾。拿 Grok Bot 写一句广告词，当然也能写，但像是为了切一个苹果，专门搬来一张工作台。

那台“不会关机的电脑”才是关键

Grok Bot 能接手工作的原因，不在聊天框，而在背后的持久云端电脑。

这台电脑有浏览器、文件系统和终端，也能使用可用的连接器、Plugins 和 MCP。我的笔记本合上以后，已经启动的任务仍可继续运行。等它碰到需要判断或授权的步骤，才会暂停。

“持久”比“云端”更关键。

普通聊天经常像一次性会议。新开一个对话，我又要解释文件在哪、格式怎么写、哪些网站优先。Bot 有自己的名字、职责、会话和保存下来的工作偏好。同一个 Bot 做得越久，越容易形成稳定上下文。

但持久也有代价。

同一账号下的多个 Bot 共用一台云端电脑。文件、浏览器登录状态、应用会话和部分凭据，可能被这些 Bot 共同看到。每个 Bot 可以有自己的屏幕，可以并行干活，却没有各自独立的安全边界。

我不能因为建了“财务 Bot”和“内容 Bot”，就以为它们隔着两堵墙。只要登录信息和文件放在共享电脑里，其他 Bot 也可能用到。分岗位能整理上下文，不能隔离敏感数据。

下载之前，先查资格，不和安装包较劲

很多新手会在这里浪费时间。软件装好了，登录后却提示没有权限，于是反复卸载、重装、换网络。问题往往不在安装包，而在账号资格。

截至我写这篇教程时，Grok Bot 已经纳入这些个人或自助团队方案：

  • SuperGrok、SuperGrok Plus、SuperGrok Heavy
  • Cursor Pro、Cursor Pro+、Cursor Ultra
  • Cursor Teams Standard 和 Premium

产品还在快速调整，资格页和帮助文档偶尔会出现更新不同步。登录自己的账号，查看 Grok Bot Access、套餐页或客户端给出的实时结果，比背名单可靠。

免费账号可能看到试用入口，但我不会把试用当成长期可用方案。试用额度、每周用量和开放范围都可能变化。正式把它放进工作流程前，我会先确认两件事：当前套餐是否包含访问资格，这项任务会消耗多少用量。

Grok Bot 有自己的使用额度，和普通 Grok 或 Cursor 的常规额度分开计算。它的消耗也不是简单按“发了几条消息”来理解。一个要跨多个页面、处理大量文件、反复核验的任务，可能比十次短对话更贵。

还有一个会卡住老 Cursor 用户的设置：Grok Bot 需要云端存储。如果账号仍在使用 Legacy Privacy Mode，客户端可能无法启动。碰到包含这个词的报错，我会先去 Cursor 的隐私设置核对数据选项，不会继续折腾安装包。团队账号则可能需要管理员处理。

为什么我买的是 SuperGrok，登录时却看见 Cursor？

这大概是整个新手流程里最让人发懵的一幕

我明明是从 Grok 那边获得使用资格，打开 Grok Bot 后，认证页面却出现 Cursor。很多人看到这里会怀疑自己下错软件，或者以为还得再买一份 Cursor 订阅。

不用急着付第二次钱

Grok Bot 当前使用 Cursor 账号体系完成登录和部分设置。拥有符合资格的 SuperGrok 方案时，可以在入口中关联 Grok 账号，再按页面完成授权。看到 Cursor，不代表必须另外购买 Cursor 会员。

如果登录后仍显示无资格，我按这个顺序排查：

  1. 先确认 SuperGrok 或 Cursor 套餐已经生效
  2. 确认浏览器和客户端使用的是同一个对应账号
  3. 退出 Grok Bot 后重新登录
  4. 回到 Access 页面重新检查资格
  5. 团队账号确认 SSO 和管理员配置
  6. 仍不识别，再走官方支持渠道

我不会通过来路不明的“代充入口”交出密码、验证码或会话 Cookie。即便某个服务只索要 User ID，我也会先核对套餐、有效期、退款和售后。省下来的几分钟，不值得拿整个账号去赌。

安装其实不难，难的是别选错版本

官方客户端目前覆盖 macOS、Windows 和 Linux。iPhone 端需要 iOS 18 或更高版本，可以查看 Bot、继续对话、上传图片或文件、接收审批提醒，也能在必要时接管云端电脑。Android 是否开放，要以当时的官方列表为准，不要安装陌生 APK。

下载入口只认官方 Grok Bot 页面。安装包的真正区别主要在系统和芯片架构

https://x.ai/bot

如果用 Mac

点击左上角苹果图标，打开“关于本机”。

看到“芯片”以及 M1、M2、M3、M4 或后续型号，我选 Apple silicon。看到“处理器”和 Intel，我选 Intel。

下载完成后打开磁盘映像，把 Grok Bot 拖进 Applications，再从“应用程序”里启动。macOS 如果弹出安全确认，先核对应用的发布者和下载地址，再点“打开”。

选错芯片版本时，应用可能直接打不开。这个故障没有什么神秘的，回到“关于本机”重新看一眼，下载正确版本即可。

如果用 Windows

打开“设置 → 系统 → 系统信息”，查看“系统类型”。多数 Intel 或 AMD 电脑使用 x64，ARM Windows 电脑选择 Arm64。不要按品牌猜架构，同一个品牌可以卖两种机器。

下载对应安装程序，运行安装，完成后从开始菜单打开。客户端会自动检查更新，也可以在“Settings → Beta → Check for Updates”里手动检查。

如果用 Linux

稳定版本会提供 Linux 构建。在下载页的 More downloads 中，Debian 和 Ubuntu 通常选 .deb，Fedora 和 RHEL 选 .rpm，其他发行版可以考虑 AppImage。

终端里运行 uname -m，看到 x86_64 就选 x64，看到 aarch64 就选 Arm64。.deb 和 .rpm 用系统包管理器安装；AppImage 需要先赋予执行权限。

旧教程可能还写着“Linux 暂不支持”。产品更新很快，这类平台信息不要靠记忆，下载页当天显示什么，我就按什么来。

第一次启动：先让云端电脑把自己准备好

打开客户端，我会看到 Get started。点击后，浏览器弹出认证页面，我在浏览器完成登录，再回到 Grok Bot

如果它长时间停住，我才开始排查：

  • 完全退出客户端后重新打开
  • 检查并安装新版本
  • 打开 Agent Computer 看实际状态
  • 尝试 Retry 或 Recover
  • 把 Reset Agent Computer 留到最后

Reset 不是“万能刷新键”。它可能让近期尚未同步的工作丢失。按钮越像一键解决，越要看清后果。我宁可先多等两分钟，也不拿已有文件试手气。

首次引导还会问我常用哪些工具。这个步骤主要用来推荐适合的 Bot，不会因为我勾选了某个应用，就自动登录或修改里面的数据。真正连接工具时，仍要单独授权。

我没有创建“万能助手”，而是给它一份窄得有点无聊的工作

云端电脑准备好以后，我终于可以创建第一个 Bot。

入口可能出现在 Meet a future teammate，也可以从侧边栏点 New，选择 Create new agent。系统先生成一个 New Agent，我再打开 Bot 菜单，进入 Edit Profile。

创建资料时，我先写好 Name、Job、Description，头像可以晚点再管。

Name 是名字，短一点，方便以后在列表里找到。

Job 是主要岗位，只写一件核心工作。

Description 是长期工作说明，写它每次都该遵守的规则。

这段描述看着不花哨，甚至有点啰嗦。可它比“你是一名世界顶级 AI 助手，帮我完成所有工作”有用得多。

万能助手的问题不在能力不够，而在岗位边界太糊。今天让我找新闻，明天让我整理发票，后天又去改网站。文件、偏好、历史和判断标准全混在一个 Bot 里，积累得越久，噪声越大。

专岗 Bot 更容易形成稳定习惯。情报员只研究，内容助理只起草，数据 Bot 只看报表。等任务真的需要协作，再让它们传递上下文。

我把长期规则放进 Description，把本周的具体任务留在消息里。这个分法非常重要。

Description 回答“你一直怎么工作”。

消息回答“你这次要做什么”。

如果我把“本周重点关注某个发布会”写进长期资料，下周它可能还抱着过期要求不放。会变化的主题、日期、预算和已完成清单，应该放进当次消息，或者保存在它每次运行前会重新读取的文件里。

第一条任务，我只让它读，不让它动

新手最容易犯的错，是刚看到 Bot 会操作网页，就马上让它群发邮件、批量改后台、自动购买或删除文件。

我反着来。

第一条任务最好满足三个条件：结果容易核对，只读取不修改，五到十分钟能跑完。上传一份普通 PDF，让它提取日期和待办，就是很合适的测试。

我会直接发下面这段：

plaintext

这条任务里没有玄学。它包含五样东西：我要什么结果，去哪里读，哪些事不能做，最后交付什么，走到哪里必须停。

我把它记成一条很实用的公式：

结果 + 资料入口 + 限制 + 交付物 + 审批点

“帮我研究一下 AI”只有主题，没有终点。Bot 不知道要看多久，不知道哪些网站可信，也不知道交一段话还是一份表格。它只能猜。猜得越多，结果越像在抽奖。

“整理最近 7 天的重要更新，优先读取指定官网和官方账号，选出 10 条，保留日期、链接和核心变化，最后给我 3 个选题，不要发布”就清楚得多。

我不需要学会复杂的 Prompt Engineering 才能用好它。我只要像给一名新同事写任务单，别把关键条件藏在自己脑子里。

我的周报任务应该怎样写

等文件任务通过，我再把 AI 情报员放到公开网页上。

这次我会这样发：

plaintext

这里最值钱的一句是“不要把搜索摘要当成证据”。

搜索摘要可能过时，也可能截掉限定条件。一个页面标题能对上，不代表版本、日期、级别、时长都正确。Bot 找候选信息时可以借助搜索结果，写进最终交付前必须打开原页面。

还会要求它保留被排除的候选项和排除理由。这样我能看出它是否按标准筛过一遍，还是把搜到的前十条机械拼起来。

怎样检查它有没有“做完”，而不是“写得像做完了”

AI 很会把答案排得整整齐齐。表格有标题，句子很通顺，链接也像真的。人一看到这种完成度，很容易先放下戒心。

不按排版验收，按证据验收。

先随机打开三条原始链接，核对标题、日期、版本和关键数字。再看它有没有用搜索摘要代替原页面，有没有把“未列出”填成一个看似合理的估算值。最后自己重算一次总数、时长或比例。

一个很典型的小错，是页面写 Basic，Bot 顺手改成 Beginner。中文里都能译成“入门”，看起来几乎没区别，可一旦任务要求保留页面原始标签，它就是错的。

时长也常出问题。页面同时出现“约 2 小时”和“1 至 3 小时”，Bot 可能直接把上限 3 小时当成固定值。正确做法是保留两个字段，写明各自来自哪里；做预算校验时，再按事先约定采用上限。

给反馈时不写“再仔细一点”。这句话没有可执行标准。会这样写：

plaintext

反馈越具体，Bot 越容易把它沉淀成长期偏好。说“你做错了”只提供情绪，说“哪一项错、以哪个页面为准、重做时哪些部分不要动”才提供修正路径。

Agent Computer 在这一步很有用。它能让我看到 Bot 打开了什么页面、是否卡在登录、有没有等待审批。可电脑画面只能证明它访问过，不能证明结论正确。最后那一层核验仍要我做。

我怎样把一项小服务推到月入 5000 美金

客户只看三件事：我交什么、哪天交、出错以后谁负责。

我把产品写成一张验收清单。每周固定一天，交 10 条经过原页面核对的行业动态、3 个可写选题、1 页摘要，再附未确认问题。报价单里不写“全自动”和“一键生成”，人工复核、客户沟通和最后签字都还在我手里。

我先赚第一笔 299

刚起步时，我没有案例、评价和客户名单。直接把月费写成 1200 美金，别人没有理由相信我。我先做一份 299 的中文轻量周报：10 条动态、3 个选题、1 页摘要、一次修改，只交文档，不代发，也不登录客户后台。

第一轮人民币报价，我把阶梯写成 299、599、999 元。299 元交轻量周报，599 元增加短帖草稿，999 元增加专题对比。它们负责测试客户更愿意买哪种结果，跑通以后我才重新计算美元月费。

299 元用来验证三个问题：客户能不能看懂，哪些栏目愿意保留，我复核一份到底要两小时还是五小时。

假设一份报告占用我两小时，毛时薪约为 299 ÷ 2 = 149.5 元。如果做完要五小时，毛时薪会掉到 299 ÷ 5 = 59.8 元。我还没扣订阅费、沟通和返工。这个数字很难看，却会逼我删掉客户不需要的栏目，把重复动作保存成 Skill。

我把人民币小单改成三档美元服务

拿到可展示的样稿和反馈后，我才去找海外客户。目标客户不是“大公司”，我只找自己能读懂业务的小团队，例如 AI 工具、跨境软件、独立开发产品和小型咨询机构。行业越窄，我越容易判断哪些更新会影响客户，也越容易发现 Bot 抓到了旧版本。

第一档是 300 美金的一次性研究冲刺。我在约定范围内核对 20 条信息，整理一张对比表，给出 3 个内容角度。交付一次，不包月。新客户可以先试一次，我也能判断双方是否适合长期合作。

第二档是每月 800 美金的周报服务。我每周交一份研究简报，每月四份，包括重要变化、原始页面、内容选题和待确认问题。客户负责发布，我负责研究与草稿。

第三档是每月 1200 美金的研究加内容包。周报之外，我再交 8 条可编辑短帖或 2 篇长文提纲。多出来的 400 美金，买的是选题判断、内容改写和额外复核，不是让 Bot 多跑几次。

5000 美金需要多少客户

目标组合是：

  • 4 个 800 美金月费客户，合计 3200 美金
  • 1 个 1200 美金月费客户
  • 每月再做 2 份 300 美金研究冲刺，合计 600 美金

算式是 4 × 800 + 1 × 1200 + 2 × 300 = 5000 美金

这代表 5 个长期客户和 2 个当月项目。按每个 800 美金客户每月复核 8 小时、1200 美金客户复核 14 小时、每份研究冲刺复核 4 小时计算，我给交付预留 4 × 8 + 14 + 2 × 4 = 54 小时。再加 20 小时找客户、开会和修改，一个月大约 74 小时

我用三个月爬这道坡

第一个月，我只盯着第一笔钱。做一份样稿，联系 30 个与选题相关的人，争取拿到 1 至 2 个测试客户。月流水能到 300 至 600 美金，说明有人愿意为交付付费。没人买，我先改领域和样稿，不买更多工具壮胆。

第二个月，我争取把一次性客户转成月费客户。目标是 2 个 800 美金客户，加 2 份 300 美金研究冲刺，计划流水 2200 美金。这个阶段最费时间的工作往往是修改服务范围、整理客户反馈和拒绝临时加活。

第三个月，我再把客户组合推到 5 个长期客户和 2 个短项目，目标流水 5000 美金。客户数量上去以后，我宁可暂停接单，也不让同一个 Bot 混用客户资料。每个客户都有单独文件夹、任务说明和验收清单，涉及登录与发布的操作继续由我批准。

我的 7 天起步表

第一天，选一个自己能判断对错的细分领域，列出 5 个固定页面。

第二天，写清周报栏目、字数、交付时间和不能做的事

第三天，创建一个专岗 Bot，用公开网页跑第一版

第四天，随机核对 3 条信息，改掉日期、版本、链接和重复问题。

第五天，把合格流程保存成 Skill，再换一个主题重跑

第六天，整理一份不含客户资料的样稿，先挂 299 元或 49 美金测试价

第七天，把样稿发给真正可能需要它的人，只问：“这份周报有没有替你省下查资料的时间？”有人付钱，我再谈月费；没人买，我改选题和交付，不急着增加更多 Bot

Grok Bot 替我压缩搜集、整理和排版，我仍要选领域、定标准、核事实、找客户。5000 美金来自 7 份写清边界的付费关系，不会从聊天框里自动长出来。

登录、验证码和 Take Over：该我上场时，我就自己来

Bot 进入需要认证的网站时，可能会要求我接管云端电脑。

打开对话里的 Agent Computer，点击 Take Over，自己输入密码、Passkey、双重验证码，或者完成 CAPTCHA。确认已经进入登录后的页面，再把控制权交还给 Bot，让它继续。

密码和一次性验证码不能发在普通聊天框里。聊天内容会进入会话上下文，风险和直接在登录页面输入完全不同。

我只接管受阻的那一步，不会顺手替它把后面的任务全做完。接管完成后，它应该沿着原任务继续。如果它忘了上下文，我会补一句：“登录已经完成，继续读取数据，只做分析，不修改后台。

登录会话保存在共享云端电脑上，其他 Bot 也可能使用。任务结束后，如果这个账号比较敏感，或者未来不再需要，我会退出登录并撤销授权。删除一个 Bot 不保证同时清掉共享电脑里的文件和会话。

Skill 不是咒语，它只是把跑通的方法保存下来

当 AI 情报员手工完成一次周报，格式、核验和审批都符合要求，我才考虑保存 Skill

顺序不能反

一个有错误的流程被保存成 Skill，不会神奇地变正确，只会更稳定地重复错误。每周准时交付同一种错，比偶尔失败更麻烦。

我会让它把已经跑通的过程保存成“每周 AI 情报周报”Skill，里面包含：

  • 每次从哪些类型的页面开始；
  • 候选信息如何筛选；
  • 哪些字段必须回原页面核对；
  • 冲突和缺失字段怎样标记；
  • 最终周报的固定格式；
  • 哪些操作必须停下来审批。

Skill 要聚焦。一组固定页面，一个输出格式，一套审批边界，已经够它反复使用。把“搜新闻、写文章、发 X、回评论、统计数据”全塞进一个 Skill，出问题时很难知道是哪一步坏了。

保存以后，我会换一个主题再测一次。第一次研究“模型更新”，第二次换成“AI Agent 工具”。如果它仍能读取新输入，没有偷偷沿用上次候选项，格式和核验规则也保持一致，这个 Skill 才算站住。

会变化的信息不应该塞进 Skill 的固定记忆。我可以在共享电脑里放一个 weekly-brief.md，写本周主题、时间范围、排除词和已处理项目。每次运行先读这份文件；文件缺失或日期过期，就报告问题并停止。

这比要求 Bot “记住我上周说过什么”可靠。记忆适合保存偏好，文件适合保存会变的事实。

Routine 让它按时跑，但我不会急着自动化

Routine 负责“什么时候执行”。Skill 负责“按照什么方法执行”。Bot 则是承担岗位的那个角色。

我把三者理解成：人、做事方法、日程表

手工流程通过以后，我才建立每周 Routine。创建时，我会明确日程、时区、输入文件、交付内容、审批边界，以及指定页面打不开时该怎么办。

我会把下面这段放进长期说明：

plaintext

客户端可能给我 Allow once、Deny、Always allow 三种选择。

我刚开始只用 Allow once。它麻烦一点，却能让我看清规则到底覆盖什么。Always allow 会让以后匹配这条规则的操作直接放行。网页按钮、流程和文案会变化，一条写得过宽的规则，几周后可能允许我当初没想到的动作。

读取公开网页、整理普通文件、生成草稿，适合逐步放宽。发消息、下单、删除数据、改权限和动生产环境，我会一直保留人工确认。

安全不是因为 AI “坏”。问题更普通：它可能理解错对象，页面可能改版，第三方内容可能诱导操作，我也可能把任务写漏。把关键动作留给人，是为了让一个小误解不会直接变成外部后果。

卡住时，我先看它在等什么

Bot 没有回话，不一定是崩了。它可能正等登录、验证码、权限审批、补充信息，或者网页还没加载完。

我打开 Agent Computer 看现场，比连续发“好了吗”有效。

如果方向错了，我发一条短而明确的新指令：“停止当前搜索，只保留已经核验的三条，按原格式交付。”需要马上终止时，直接发 Stop now。

下面是我会遇到的几类故障。

登录成功但客户端没切回来：保持 Grok Bot 开着，手动切回，再点一次 Sign In with Cursor。团队账号检查 SSO。

云端电脑一直初始化：先看进度是否还在变化，再重启客户端、检查更新、Retry 或 Recover。Reset 最后用。

网站反复要求登录：我接管电脑，完成验证码，等登录后页面真正加载出来，再交回控制权。有些网站会主动让会话过期，这不一定是 Bot 故障。

附件读不到：先检查文件是否加密、是否仍在上传、格式是否太特殊。常见限制会随版本变化，遇到大文件或视频要先看客户端当时提示。特殊格式可以转成 PDF、CSV、纯文本或图片再试。

结果一直跑偏：先检查岗位是否太宽、当次任务有没有边界、长期说明是否和临时要求冲突、变化信息是不是被错误地留在记忆里。把这四处逐一检查，比换十种花哨提示词更有效。

小白最稳的升级路线

我不会第一天就让 Grok Bot 管邮箱、做客服、改后台。那样看起来进步很快，每一步出了错却很难定位。

我会沿着风险逐级上升：

  1. 先总结一份普通 PDF，核对页码和日期；
  2. 再研究公开网页，要求打开原页面并保留链接；
  3. 然后登录网站，只读信息，不做修改；
  4. 让它生成邮件、文章或方案草稿，但不发送；
  5. 对一项可撤销操作使用 Allow once；
  6. 同一流程手工跑通并换输入测试后，再保存 Skill；
  7. 最后才建立 Routine，并立即试跑一次。

这条路线看着慢，排错反而省时间。前一层稳定，后一层出错时我才知道问题来自新增加的权限或动作。第一天就全开，最后只能得到一句含糊的结论：“AI 不靠谱。”

工具当然会犯错，人写的任务也会漏条件。把它们分开检查，我才有机会把流程修好。

我用的三段模板

如果你不想回头翻全文，下面三段可以直接改

模板一：Bot 的长期资料

名称：资料研究员主要工作：读取我指定的公开网页和文件，整理可核验的信息。工作说明：优先使用我指定的页面和一手资料。每条重要结论保留日期、原始链接或文件页码。把已确认事实、推测和建议分开。资料没有说明时写“未说明”，不要猜。任何登录、发送、发布、购买、付款、删除、覆盖、批量修改、权限变更、生产环境操作和协议接受，都必须先停下来请求批准。

模板二：一次性研究任务

在最近 7 天的时间范围内，整理指定主题的重要更新。先从我给出的官网和官方账号寻找候选信息。不要把搜索摘要当成证据，纳入结果前必须打开原页面。每条结果包含标题、日期、核心变化、原始链接和选择理由。页面未列出的字段写“未列出”，不要估算。信息冲突时并列展示，不要自行裁决。最后返回摘要、结果清单、被排除的候选项及理由、仍需我确认的问题。只交付草稿，不要发布、发送或修改任何外部内容。

模板三：高风险动作审批

准备发送、发布、购买、付款、删除、覆盖、批量修改、改变权限、修改生产环境或接受协议时，立即停止。先展示操作对象、当前状态、准备执行的内容、可能影响和撤销方式。只有得到我针对这一次操作的明确批准后才能继续。未批准时，只能提供预览或草稿。

模板不用一字不改地照搬。记住背后的结构就够了：岗位要窄，任务要有结果，事实要能核对，外部动作要有刹车。

不再问“它有多聪明”

用聊天 AI 时，我最常问的是：“它能不能回答这个问题？”

到了 Grok Bot，我换了一个问法：“这项工作，我能不能把目标、资料、边界和验收标准说清楚？”

说不清楚，我就不该急着自动化。一个人都没想明白的流程，交给 Bot 只会更快地变成一团乱麻。

说清楚以后，事情才有意思。Bot 有名字、有岗位，有一台持续运行的电脑；Skill 记住做事方法，Routine 负责按时启动，审批规则在关键位置把它拦住。我不必盯着每一次点击，也不用把整个账号扔给它不管。

我现在的起点仍然很小：一份普通文件，一个只读任务，一个叫得出名字的 Bot。

它把小事做对以后，我拿出第一份样稿，挂上 299 元或 49 美金测试价。有人付钱，我继续磨交付；没人付钱，我回去改领域、栏目和客户名单。工具数量在这一步没有用。

月入 5000 美金听上去像一个很大的结果，拆开以后只有一张朴素的算式：4 个 800 美金客户、1 个 1200 美金客户、2 份 300 美金项目。算式外还有更费劲的活：我得让 7 份交付准时、准确、彼此隔离，还要不断找到下一个愿意续费的人。

所以我从第一条只读任务开始。等我看得懂 Bot 做了什么、错在哪里、怎样纠正，再把下一把钥匙交出去。5000 美金是终点线，第一份可核验的周报才是起跑线。
